### 1. 디지털 데이터 압축의 이해
- **데이터 압축**: 한정된 저장 공간에 데이터를 효율적으로 기록하기 위한 기술로, 저장할 데이터를 더 적은 수의 비트로 표현한다. (p.40)
- **비트**: 컴퓨팅 시스템에서 정보 표현의 최소 단위 (p.40)
- 압축의 효과: 저장 공간 절약 + 네트워크 전송 시간 단축 → 컴퓨터 자원을 효율적으로 활용 (p.40)
  - 저장 및 전송 단계: 저장 공간을 적게 사용한다 / 네트워크 전송 시 속도가 빨라진다 / 디지털 탄소 중립을 실천할 수 있다.
- 압축은 두 과정으로 이루어진다. (p.40)
  - **인코딩(encoding)**: 디지털 데이터의 비트 수를 줄이기 위해 데이터를 다른 형태로 변환하는 과정. 데이터를 특정 형식이나 코드로 변환하는 과정으로, **부호화, 암호화, 코드화**라고도 한다.
  - **디코딩(decoding)**: 인코딩된 압축 데이터를 원래 형태로 복원하는 과정. **복호화, 역코드화**라고도 한다.
- 압축·복원 과정 그림: 입력(문자, 소리, 이미지 등 데이터 입력) → 인코딩(전체 비트 수를 줄여 압축) → 저장 및 전송 → 디코딩(압축 전 데이터로 복원) → 출력 (p.40)
- 압축 방식은 **인코딩 과정에서 데이터 유실 여부**에 따라 나뉜다. (p.40)
  - **비손실 압축**: 압축 후 복원했을 때 입력 데이터와 출력 데이터가 **같다**.
  - **손실 압축**: 압축 후 복원했을 때 입력 데이터와 출력 데이터가 **다르다**.
- 도입 만화 예: "사진이 저장 공간을 다 차지했네", "사진 전송이 오래 걸리네 → 압축해서 전송해 봐", "용량이 가장 적은 음원으로 압축해서 담아 왔는데 음질이 왜 이러지?"(손실 압축의 결과) (p.40)

### 2. 문자열 압축
- 컴퓨팅 시스템은 문자 데이터를 **문자 집합의 이진 코드**로 표현한다. (p.41)
  - **문자 집합(character set)**: 사람이 사용하는 문자를 컴퓨터가 이해하는 코드로 표현한 것. 아스키코드, 유니코드 등이 있다.
- 문자열은 문자들의 집합 → 반복되는 같은 문자나 부분 문자열을 더 적은 수의 비트로 표현해 압축한다. (p.41)
- 문자열 압축은 **비손실 압축** 방식을 사용한다. 가장 간단한 비손실 압축 알고리즘: **런-렝스(Run-Length) 인코딩**, **렘펠-지브(Lempel-Ziv) 인코딩** (p.41)

#### ① 런-렝스 인코딩
- 연속해서 반복되는 같은 문자를 **반복 문자 개수와 반복 문자의 쌍**으로 표현하는 인코딩 알고리즘 (p.41)
- 장점: 알고리즘이 단순하고, **반복되는 문자가 길게 나타날수록** 압축 효율이 높다. (p.41)
- 반복 없는 문자의 경우 반복 문자 개수 1을 **생략**해서 압축 효율을 더 높일 수 있다. (p.41)
- **숫자가 포함된 문자열의 압축**: 원래 문자열에 숫자가 있으면, 출현 빈도가 적은 문자를 **탈출 문자('*')**로 사용해 반복 문자 개수와 구분한다. 예: `"AB3AAAA" → "AB3*4A"` (p.41)
- 런-렝스 알고리즘은 문자열뿐 아니라 **흑백 그림, 팩스 정보, 단색의 만화** 등 반복되는 정보가 많을 때 효율적이다. (p.43)

#### ② 렘펠-지브 인코딩
- 문자열에 포함된 **같은 패턴의 상대적 위치와 패턴의 길이**로 문자열을 치환하여 압축하는 방법 (p.41)
- 장점: **떨어져 있는 같은 패턴도** 압축이 가능하다. 반복 패턴이 많이 포함된 **긴 문자열**에서 압축 효율이 높다. (p.41)
- 그림 표기 예: (5, 3) → 5는 현재 위치에서 왼쪽으로 5칸 이동하기, 3은 패턴의 길이(반복될 문자 개수). 즉 "현재 위치에서 5문자 앞에서부터 3문자의 문자열 반복하기" (p.41)

#### 다양한 압축 알고리즘
- 실제로는 압축 효율을 높이기 위해 런-렝스, 렘펠-지브뿐 아니라 **문자 출현 빈도에 따라 다른 길이의 이진 코드를 할당**하는 등 다양한 알고리즘이 결합·변형·확장되어 사용된다. (p.41)

### 3. 이미지 압축
- **비트맵 이미지**: 화소들이 모인 하나의 이미지. 전체 화소 수와 표현 색상이 많을수록 섬세한 고해상도 이미지를 표현할 수 있지만 **용량이 커지는** 단점이 있다. → 사용 목적에 맞게 형식을 변환·압축하면 효율적 (p.42)
- **화소(픽셀)**: 컴퓨터에서 이미지를 구성하는 최소 단위 (p.42)
- 각 화소에 할당되는 비트 수와 표현 가능한 색상 수 (p.42)
  - 1비트: 단색 (2¹ = 2)
  - 8비트: 256색 (2⁸ = 256)
  - 24비트: RGB 트루 컬러 (2²⁴ = 16,777,216) — Red, Green, Blue 각각 0~255

#### ① BMP 파일
- 각 화소에 색 정보를 차례대로 기록하는 **무압축** 파일 형식, 확장자 `.bmp` (p.42)
- 각 화소에 1~24비트 색 표현 가능, 압축하지 않아 이미지 품질이 매우 우수 (p.42)
- 단점: 파일 크기가 커서 많은 공간을 차지하고 인터넷 공유가 어렵다. (p.42)
- 용도: 고품질의 사진이나 사이즈가 작은 아이콘 (p.42)

#### ② 이미지 압축 파일 (PNG, GIF, JPEG) (p.43)
- **PNG**: 비손실 압축, 트루 컬러(24비트). 반복되는 색 정보를 더 적은 비트로 줄이는 비손실 압축 알고리즘 사용 → 이미지 손실 없이 고품질 이미지 처리 가능. `.png`
- **GIF**: 손실 압축·비손실 압축, 256색(8비트). 지원 색상이 256색이라 파일 크기가 작다. 256색 이미지는 손실 없이 압축되지만, **256색 이상의 이미지는 지원 가능한 색으로 변환되므로 손실이 발생**한다. `.gif`
- **JPEG**: 손실 압축, 트루 컬러(24비트). 사람 눈으로 인식하지 못하는 범위의 색 차이와 이미지의 세밀한 부분의 정보를 제거해 크기를 줄인다. 압축률이 높아 파일이 작지만 이미지 손실 발생. `.jpg, .jpeg, .jpe, .jfif`
- 비교 예: BMP(원본) 236KB / GIF 59KB / PNG 142KB / JPEG 8KB → JPEG는 손실 압축으로 압축 효율이 높아 파일 크기가 가장 작다. (p.43)

#### 활동 1 — 비트맵 그림을 런-렝스로 압축 (p.42~43)
- 픽셀아트 사이트(https://www.pixilart.com/)에서 [START DRAWING] → 너비 7, 높이 8 화소 입력 후 [New Drawing] → [pencel tool]로 각 화소 색 지정 (7×8 크기 그림)

### 4. 소리 압축
- 컴퓨터는 진동으로 만들어진 아날로그 소리 신호를 그대로 디지털로 변환하는 **웨이브 방식**으로 소리를 표현한다. 모든 소리를 디지털로 표현할 수 있어 유용하지만 **용량이 크다**. (p.44)

#### ① WAV 파일
- 웨이브 방식의 디지털 신호를 **압축하지 않은 무압축** 파일 형식, 확장자 `.wav` (p.44)
- 아날로그 신호 → **표본화 → 양자화 → 부호화** → 디지털값 (p.44)
  1. **표본화**: 아날로그 소리 파형을 일정 간격으로 나누어 샘플 신호의 값을 측정한다.
  2. **양자화**: 소리의 크기를 가까운 정숫값으로 표현한다.
  3. **부호화**: 각 정수를 0과 1의 디지털값으로 표현한다. (그림 예: 2→010, 3→011, 4→100, 5→101)
- 표본화에서 샘플 추출 **간격이 좁을수록**, 추출된 신호를 표현하는 **비트 수가 많을수록** 원음에 가까운 소리 (p.44)
- WAV는 CD 음원(44,100개 샘플, 16비트) 그대로를 손실 없이 표현 → 녹음이나 전문 오디오 프로젝트에 주로 활용. 하지만 용량이 매우 커서 FLAC, MP3, AAC 등으로 변환해 활용 (p.45)
- **CD 음원(44.1kHz/16bit)**: 1초에 44,100개의 샘플을 추출하여 16비트(2¹⁶ = 65,536개)로 서로 다른 소리 데이터를 표현 (p.45)
- **CD 1초 용량** (p.45)
  - `샘플 수 × 비트 수 × 채널 수 = 44,100 × 16 × 2 = 1,411,200bit = 176,400byte ≒ 0.16MB`
- **비트 전송률**: 음원이 재생될 때 초당 읽어 들이는 비트 수. 비트 전송률이 **낮을수록 음질이 떨어진다**. (p.45)

#### ② 소리 압축 파일 (FLAC, MP3, AAC) (p.45)
- **FLAC**: 비손실 압축. 무음과 반복 구간은 더 적은 비트로 표현하고, 원음의 파형을 예측할 수 있는 수식과 실제 데이터의 차이만 저장해 용량을 줄인다. 소리 데이터 손실 없음. `.flac`
- **MP3**: 손실 압축. 사람이 잘 듣지 못하는 대역의 신호를 제거해 용량을 줄임 → 손실 발생. 비트 전송률로 음질을 조절해 압축 가능. `.mp3`
- **AAC**: 손실 압축. MP3와 같은 방식으로 신호를 제거하지만 **MP3에 비해 음질이 더 좋다**. 비트 전송률로 음질 조절 가능. 확장자 `.m4a`
- 스펙트럼(spek) 비교 예: WAV(원음) 7.76MB / FLAC 4.01MB / MP3(128kbps) 361KB / AAC(128kbps) 366KB → 손실 압축(MP3)이 압축 효율이 높아 파일 크기가 가장 작다. (p.45)

### 선택 활동 — 데이터를 압축하여 효율성 분석하기 (p.46~47)
1. 입력 문자열 `oopsssss didn’t see you`를 런-렝스 인코딩으로 압축하고 입력 문자열 길이, 압축 후 문자열, 압축 후 문자열 길이를 적는다. (p.46)
2. 온라인 이미지 변환 사이트(https://convert.io/ko/image-converter)에서 BMP → JPG 변환, 품질(quality) 조정: BMP 236KB → 품질 80% 21KB, 품질 50% 13KB (p.47)
3. 온라인 오디오 변환 사이트(https://online-audio-converter.com/ko/)에서 WAV → MP3 변환 후 용량과 비트 전송률 확인. WAV 파일 예: 용량 7.76MB, 비트 전송률 2,822kbps. [파일 탐색기]에서 소리 파일 오른쪽 클릭 → [속성] - [자세히]로 확인 (p.47)

- 스스로 평가하기: 문자열, 이미지, 소리를 압축하고, 압축 효율을 분석할 수 있는가? (p.47)

#### 프로그램 맛보기 — 런-렝스 인코딩 알고리즘으로 문자열 압축하기 (p.46)
```python
x = input("압축 전 문자열을 입력하세요: ")
result = ""
cnt = 1
for i in range(1, len(x)) :
  if x[i-1] == x[i] :
    cnt += 1
  else :
    if cnt > 1 :
      result += str(cnt) + x[i-1]
    else :
      result += x[i-1]
    cnt = 1
# 마지막 문자 출력을 위해 반복 횟수가 2 이상이면 ‘반복 문자 횟수 + 문자’ 입력하기
if cnt > 1 :
  result += str(cnt) + x[i-1]
else :
  result += x[i]
print("압축 후 문자열: ", result)
print("압축 전 문자열 길이: ", len(x))
print("압축 후 문자열 길이: ", len(result))
```
줄별 동작(교과서 주석 기준)
- 01행: 압축 전 문자열을 입력받아 x에 저장한다.
- 02행: 압축 후 문자열을 저장할 변수 result를 빈 문자열로 만든다.
- 03행: 문자 반복 횟수 변수 cnt를 1로 시작한다.
- 04행: i가 1부터 '문자열 길이-1'까지 반복한다.
- 05~06행: 앞 문자 x[i-1]과 현재 문자 x[i]가 같으면 반복 횟수를 1 증가한다.
- 07행: 다음 문자와 같지 않으면(반복이 끊기면)
- 08~09행: 반복 횟수가 2 이상이면 '반복 문자 횟수 + 문자'를 result에 붙인다(str()로 숫자를 문자열로 바꿈).
- 10~11행: 반복 횟수가 1이면 '문자'만 붙인다(개수 1 생략).
- 12행: 반복 횟수를 1로 초기화한다.
- 13~17행: 반복문이 끝난 뒤 마지막 문자 묶음을 처리한다. 반복 횟수가 2 이상이면 '횟수 + 문자', 1이면 '문자'만 붙인다.
- 18~20행: 압축 후 문자열, 압축 전 문자열 길이, 압축 후 문자열 길이를 출력한다.
- 풀이(코드 추적): `oopsssss didn’t see you` 입력 시 → 압축 후 `2op5s didn’t s2e you`, 압축 전 길이 23, 압축 후 길이 20

## 비교·정리표

### 인코딩 vs 디코딩
| 구분 | 인코딩 | 디코딩 |
|---|---|---|
| 하는 일 | 비트 수를 줄이기 위해 다른 형태로 변환(압축) | 압축 데이터를 원래 형태로 복원 |
| 다른 이름 | 부호화, 암호화, 코드화 | 복호화, 역코드화 |
| 위치 | 입력 → 인코딩 → 저장·전송 | 저장·전송 → 디코딩 → 출력 |

### 런-렝스 vs 렘펠-지브
| 구분 | 런-렝스 인코딩 | 렘펠-지브 인코딩 |
|---|---|---|
| 표현 방법 | 반복 문자 개수 + 반복 문자의 쌍 | 같은 패턴의 상대적 위치 + 패턴의 길이 |
| 효율이 높은 경우 | 같은 문자가 연속해서 길게 반복될 때 | 반복 패턴이 많은 긴 문자열 |
| 장점 | 알고리즘이 단순 | 떨어져 있는 같은 패턴도 압축 가능 |
| 압축 종류 | 비손실 | 비손실 |

### 이미지 파일 형식
| 형식 | 압축 방식 | 지원 색상 | 특징 | 확장자 | 예시 용량 |
|---|---|---|---|---|---|
| BMP | 무압축 | 1~24비트 | 품질 매우 우수, 크기 큼, 인터넷 공유 어려움 | .bmp | 236KB |
| PNG | 비손실 | 트루 컬러(24비트) | 반복 색 정보를 적은 비트로, 고품질 | .png | 142KB |
| GIF | 손실·비손실 | 256색(8비트) | 256색 넘으면 손실 | .gif | 59KB |
| JPEG | 손실 | 트루 컬러(24비트) | 눈이 못 느끼는 색 차이·세밀한 정보 제거 | .jpg, .jpeg, .jpe, .jfif | 8KB |

### 소리 파일 형식
| 형식 | 압축 방식 | 특징 | 확장자 | 예시 용량 |
|---|---|---|---|---|
| WAV | 무압축 | 웨이브 방식, CD 음원 그대로, 녹음·전문 오디오 | .wav | 7.76MB |
| FLAC | 비손실 | 무음·반복 구간 적은 비트, 예측 수식과 실제 차이만 저장 | .flac | 4.01MB |
| MP3 | 손실 | 잘 안 들리는 대역 제거, 비트 전송률로 음질 조절 | .mp3 | 361KB(128kbps) |
| AAC | 손실 | MP3 방식이지만 음질 더 좋음 | .m4a | 366KB(128kbps) |

### 소리의 디지털 변환 3단계
| 단계 | 하는 일 |
|---|---|
| 표본화 | 파형을 일정 간격으로 나누어 샘플 값 측정 |
| 양자화 | 소리 크기를 가까운 정숫값으로 |
| 부호화 | 정수를 0과 1의 디지털값으로 |

## 시험 함정 포인트
- 손실/비손실은 압축률이 아니라 **인코딩 과정에서 데이터가 유실되는지(복원 시 입력과 출력이 같은지)**로 나눈다. (p.40)
- 인코딩의 다른 이름에는 '암호화'도 있다. 디코딩은 '복호화, 역코드화'다. 둘을 바꿔 쓰지 않는다. (p.40)
- 문자열 압축은 손실 압축이 아니라 **비손실 압축**을 사용한다. (p.41)
- 런-렝스는 '떨어져 있는 같은 패턴'을 잘 압축하는 것이 아니라 **연속 반복** 문자에 강하다. 떨어진 패턴도 압축 가능한 것은 **렘펠-지브**다. (p.41)
- 숫자가 섞인 문자열에서 탈출 문자로 쓰는 것은 자주 나오는 문자가 아니라 **출현 빈도가 적은 문자('*')**다. `"AB3AAAA" → "AB3*4A"` (p.41)
- BMP는 압축 파일이 아니라 **무압축** 파일이다. WAV도 **무압축**이다. (p.42, p.44)
- GIF는 '항상 손실'이 아니다. 256색 이미지는 손실이 없고, **256색 이상**이면 손실이 생긴다(손실·비손실 모두 해당). (p.43)
- PNG는 손실 압축이 아니라 **비손실** 압축이며 트루 컬러(24비트)를 지원한다. GIF만 256색(8비트)이다. (p.43)
- FLAC은 손실 압축이 아니라 **비손실** 압축이다. MP3·AAC가 손실 압축이다. (p.45)
- AAC의 확장자는 .aac가 아니라 교과서 표에서 **.m4a**다. (p.45)
- 비트 전송률이 **낮을수록** 음질이 떨어진다(높을수록 좋은 것이 아님을 반대로 외우지 않기). (p.45)
- CD 1초 용량 계산에는 샘플 수·비트 수뿐 아니라 **채널 수(2)**도 곱한다: 1,411,200bit = 176,400byte ≒ 0.16MB. (p.45)
- 원음에 가까워지려면 표본화 간격은 **좁게**, 비트 수는 **많게**. (p.44)
- 화소당 24비트는 2²⁴ = 16,777,216색(트루 컬러), 8비트는 256색, 1비트는 2색(단색). (p.42)

## 핵심 용어 사전
| 용어 | 뜻 |
|---|---|
| 데이터 압축 | 저장할 데이터를 더 적은 수의 비트로 표현하는 기술 |
| 비트 | 컴퓨팅 시스템에서 정보 표현의 최소 단위 |
| 인코딩 | 데이터를 특정 형식이나 코드로 변환하는 과정(부호화, 암호화, 코드화) |
| 디코딩 | 인코딩된 데이터를 원래 형태로 복원(복호화, 역코드화) |
| 비손실 압축 | 복원 시 입력 데이터와 출력 데이터가 같은 압축 |
| 손실 압축 | 복원 시 입력 데이터와 출력 데이터가 다른 압축 |
| 문자 집합 | 사람의 문자를 컴퓨터가 이해하는 코드로 표현한 것(아스키코드, 유니코드) |
| 런-렝스 인코딩 | 연속 반복 문자를 '반복 개수 + 문자' 쌍으로 표현 |
| 렘펠-지브 인코딩 | 같은 패턴의 상대적 위치와 길이로 치환 |
| 탈출 문자 | 숫자가 있는 문자열에서 반복 개수와 구분하려고 쓰는, 출현 빈도가 적은 문자('*') |
| 비트맵 이미지 | 화소들이 모인 하나의 이미지 |
| 화소(픽셀) | 이미지를 구성하는 최소 단위 |
| 트루 컬러 | 24비트 RGB, 2²⁴ = 16,777,216색 |
| BMP | 무압축 이미지 형식(.bmp) |
| PNG | 비손실 압축, 트루 컬러(.png) |
| GIF | 256색, 손실·비손실 압축(.gif) |
| JPEG | 손실 압축, 트루 컬러(.jpg 등) |
| 웨이브 방식 | 아날로그 소리 신호를 그대로 디지털로 변환하는 소리 표현 방식 |
| WAV | 웨이브 방식의 무압축 소리 형식(.wav) |
| 표본화 | 파형을 일정 간격으로 나누어 샘플 값을 측정 |
| 양자화 | 소리 크기를 가까운 정숫값으로 표현 |
| 부호화 | 정수를 0과 1의 디지털값으로 표현 |
| CD 음원 | 44.1kHz/16bit, 1초에 44,100개 샘플을 16비트로 표현 |
| 비트 전송률 | 음원 재생 시 초당 읽는 비트 수, 낮을수록 음질 저하 |
| FLAC | 비손실 소리 압축(.flac) |
| MP3 | 잘 안 들리는 대역을 제거하는 손실 소리 압축(.mp3) |
| AAC | MP3 방식이지만 음질이 더 좋은 손실 압축(.m4a) |
| 라디오 존데 | 대기 상층의 기상을 관측하는 장치 |
