# Ⅲ-01 문제 분해와 모델링
교과서 75-91쪽 · 정보

## 학습 목표
- 컴퓨터를 이용한 문제 해결 과정을 설명할 수 있다. (p.80)
- 복잡한 문제를 해결 가능한 작은 문제로 분해하고 핵심 요소를 추출할 수 있다. (p.80)
- 문제 해결에 필요한 데이터 간의 관계를 분석하고 모델링할 수 있다. (p.80)
- 무엇을 배울까? — 생활 속 복잡한 문제를 해결하기 위해 어떻게 해야 할까? 생활 속 복잡한 문제를 찾아 단순하게 표현해 보자. / 핵심 요소: 문제 분석, 문제 분해, 핵심 요소 추출, 모델링 (p.80)

## 핵심 개념

### 대단원 Ⅲ 도입 — 알고리즘과 프로그래밍
- 소단원 구성: 01 문제 분해와 모델링, 02 알고리즘, 03 프로그래밍의 이해, 04 제어 구조의 응용, 05 함수와 라이브러리, 06 객체지향 프로그래밍, 07 창의 융합 프로그래밍 (p.76)
- 생각해 보자: 문제 분해와 모델링으로 문제 해결 모델 설계하기 / 알고리즘의 수행 과정 및 효율성 비교·분석하기 / 복잡한 문제를 프로그래밍으로 해결하기 (p.77)
- **생각에 날개 달기 — 놀이공원에서의 즐거운 하루**: 성진이가 정문에서 이벤트 홀까지 가는 가장 빠른 길을 컴퓨터로 찾는 과정 (p.78~79)
  - 컴퓨터를 이용한 문제 해결 흐름: **문제 분석 → 문제 분해 → 모델링 → 알고리즘 설계 → 프로그래밍 → 결과 평가 및 개선**
  - 문제 분석: "목적지까지 경로가 많네" / 핵심: "분수 광장을 경유해야 해!" / 모델링: 놀이기구만 뽑아 표, 트리, 그래프로 표현 — "거리도 알 수 있어서 그래프가 좋다"
  - 알고리즘 설계: 그래프 구조에서 최적 경로 탐색 → 최적 경로는 **정문 → 분수 광장 → 바이킹 → 이벤트 홀**
  - 프로그래밍: 파이썬으로 구현. 놀이공원 안의 다른 문제 — 키 제한 조건 확인하기(조건문), 탑승 순서 알아보기(함수, "한번에 30명 탑승하는데 우린 몇 번째?"), 간식 메뉴 정하기(모델링, 알레르기)
- 도입 만화(동아리 홍보): 친구 관계를 정리 → 복잡하니 작은 문제로 나누기 → 불필요한 요소를 삭제하며 꼭 필요한 요소만 추출(핵심 요소) → 친구 관계를 그래프와 표로 표현 (p.80)

### 1. 문제 분석
- **문제**: 우리가 해결해야 할 **구체적이고 명확한 요구 사항** (p.81)
- **문제 분석**: 문제를 명확하게 이해하고 주어진 문제 상태와 요구 사항 및 제약 조건을 정의하기 위해 수행한다. (p.81)
- 문제 분석의 세 질문 (p.81)
  1. 문제의 **현재 상태와 목표 상태**는 무엇인가?
  2. 문제의 **요구 사항**은 무엇인가? (문제가 해결하고자 하는 것을 이해하는 것)
  3. 문제의 **제약 조건**은 무엇인가?
- **예제 1 — 퍼레이드 로봇** (p.81)
  - 문제 상황: N × N(N: 1~100) 격자 놀이공원에서 이동 계획에 따라 움직이는 로봇이 도착한 최종 좌표 P를 출력. 시작 좌표 S(1, 1), 격자를 벗어나는 이동은 무시
  - 이동 명령: L 왼쪽, R 오른쪽, U 위, D 아래로 한 칸
  - 입출력 예: 격자 3, 이동 `R R D R D L` → (3, 2) / 격자 4, 이동 `D D R R U R` → (2, 4)
  - 풀이: 현재 상태 — 로봇이 시작 좌표 S(1,1)에 있다 / 목표 상태 — 도착한 최종 좌표를 출력 / 요구 사항 — 이동 계획에 따라 최종 도착 좌표 출력 / 제약 조건 — 상하좌우 한 칸씩 이동, 격자 밖 움직임은 무시
  - 추적(3×3): (1,1) →R (1,2) →R (1,3) →D (2,3) →R 무시 →D (3,3) →L (3,2)

### 2. 추상화
- **추상화**: 복잡한 문제를 단순화하는 것으로, 먼저 문제를 작은 단위로 분해한 후 불필요한 요소는 제거하고 꼭 필요한 핵심 요소만 뽑아내는 과정 (p.82)
- 추상화 과정: **문제 분해 → 핵심 요소 추출 → 모델링** (p.82)
- 예: 넓고 복잡한 놀이공원(추상화 전) → 주요 놀이 시설(롤러코스터, 지구별, 식당가, 바이킹, 정문, 자이로스윙, 판다 세상, 빨간 풍차, 아마존 급류)로 표현(추상화 후) (p.82)
- 활동 1: 집에서 학교까지 버스 노선을 추상화할 때 불필요한 요소(예: 자전거 도로 등)와 필수 요소(예: 목적지를 경유하는 버스 번호)를 찾기 (p.82)
- 추상화와 모델링의 차이: 추상화는 문제의 복잡성을 단순화하고 중요한 특징을 강조하는 과정으로, **문제 분해·핵심 요소 추출·모델링이 모두 포함**된다. 모델링은 추상화의 한 과정이다. (p.85)

#### ① 문제 분해 (p.83)
- **문제 분해**: 복잡한 문제를 해결하기 쉽게 작은 문제로 나누는 과정
- 문제 사이의 **관계나 순서에 유의**하여 분해해 먼저 해결하고, 그 결과를 **종합**하면 전체를 해결할 방법을 찾을 수 있다.
- **예제 2**(예제 1 분해): 분해1 로봇의 현재 좌표를 계산하는 부분 / 분해2 이동 계획에 따라 로봇을 이동시키는 부분 / 분해3 격자 공간을 벗어난 이동을 감지하는 부분 / 분해4 로봇의 최종 도착 좌표를 반환하는 부분

#### ② 핵심 요소 추출 (p.83)
- **추상화의 가장 중요한 단계**. 문제 해결과 관련 없는 불필요한 요소를 제거하고 꼭 필요한 핵심 요소를 추출
- 여러 정보와 사실을 구분하기 위한 **기준**이 있어야 하며, 그 기준은 **문제 해결의 목적에 따라 달라질 수 있다**.
- **예제 3**(예제 1 핵심 요소): 3×3 크기의 격자 공간, 이동 계획, 퍼레이드 로봇(좌표)

#### 예제 4 — 카페 키오스크 프로그램 (p.84)
- 문제 상황: 손님이 메뉴와 수량을 선택하면 결제 금액을 알려 주고, 주문 후 주문 번호 출력. 주문 번호는 매일 아침 0으로 초기화, 연속 번호(첫 주문 1번, 두 번째 2번)
- 현재 상태: 주문을 받지 않은 상태 / 목표 상태: 주문을 받아 결제 금액과 주문 번호를 출력한 상태
- 세 개로 분해: 분해된 문제 1 메뉴·수량·금액(주문) → 분해된 문제 2 결제 금액 출력 → 분해된 문제 3 주문 번호 출력
- 핵심 요소 <보기>: 메뉴명, 대기 시간, 주문 번호, 결제 방식, 고객 이름, 메뉴 가격, 주문 금액, 수량, 신용 카드, 포장, 배달 → 교과서 풀이에 나온 핵심 요소: 메뉴(메뉴명·가격)·수량, 주문 금액, 주문 번호
- 화면 예: 초코 라테 3500원, 카페모카 4500원, 코코아 2500원 (3500×1 + 4500×1 + 2500×1 = 총액 10500원), 주문 번호 138

### 3. 모델링
- **모델링(modeling)**: 분해한 문제에서 추출한 핵심 요소들을 이해하기 쉽게 **표, 트리, 그래프** 등으로 단순화하거나 구조화하는 과정. 추상화의 한 과정 (p.85)
- 모델링으로 만든 모델은 데이터 간의 관계나 흐름을 쉽게 이해할 수 있어 문제를 효율적으로 해결하는 데 도움 (p.85)
- **모델(model)**: 문제 해결에 필요한 핵심 요소들 간의 관계를 추상적으로 표현한 모형 (p.85)
- 해결하려는 문제의 특성에 따라 **적합한 모델링 방법을 선택**할 수 있어야 한다. (p.85)
- 사례 — **런던 지하철 노선도**: 1908년 노선도는 지도 위에 역과 노선을 표현해 정보가 너무 많아 복잡 → **해리 벡(Beck, Harry)**이 선과 기호만으로 단순하게 표현해 한눈에 목적지와 방향을 볼 수 있게 바꿈 (p.85)

#### ① 표 (p.86)
- 데이터를 **가로축(행)과 세로축(열)**으로 나누어 표현하는 구조. 조건들을 비교·평가하거나 복잡한 문제들을 보기 쉽게 정리
- 사례: 거래 내역 관리, 프로젝트 일정 관리, 학생 성적 관리
- 예: 놀이공원 이용권별 요금 — 주간권 대인 56,000원/청소년 47,000원/소인·경로 44,000원, 야간권(16시~) 46,000원/40,000원/37,000원
- **활동 2 — 식품 알레르기 표** (p.86)
  - 메뉴: 구슬 아이스크림(①②⑤), 닭강정(②③④⑤⑦⑧⑨⑩⑪), 추로스(②④⑤), 치즈 핫도그(①②④⑤⑥⑦⑧⑨⑩⑪)
  - 알레르기: ① 난류 ② 우유 ③ 땅콩 ④ 대두 ⑤ 밀 ⑥ 돼지고기 ⑦ 토마토 ⑧ 아황산염 ⑨ 닭고기 ⑩ 쇠고기 ⑪ 조개류(굴, 전복, 홍합 포함)
  - 풀이: 모든 메뉴에 포함된 물질 → **우유, 밀** / 땅콩·돼지고기·조개류 알레르기가 있는 사람이 먹을 수 있는 음식 → **구슬 아이스크림, 추로스**

#### ② 트리 (p.87)
- 데이터 간 관계를 **계층적으로** 표현하기에 적합한 구조. 나무의 뿌리에서 가지가 뻗는 모습을 거꾸로 표현
- **루트 노드(root node)**: 상위 노드가 없는 최상위 노드. 그 밑에 하위 노드를 연결
- **상위 노드에서 하위 노드로만** 간선이 존재하고, 노드 간 **사이클(순환)은 허용하지 않는다**.
- 사례: 컴퓨터 폴더 구조, 조직도, 동물의 분류(동물 → 육식 동물[사자, 호랑이], 초식 동물[기린, 얼룩말])
- **노드(node)**: 데이터 항목을 나타내는 것으로 도형상의 정점
- **간선(edge)**: 데이터의 흐름이나 관계를 선으로 나타낸 것
- **사이클(cycle)**: 특정 노드에서 출발해 간선과 노드들을 지나 다시 처음 노드로 되돌아오는 순환 구조

#### ③ 그래프 (p.87)
- 데이터 간 **연결 관계를 노드와 간선**으로 표현하는 구조
- 화살표로 데이터의 **방향성**을 표현할 수 있고, 간선 위에 데이터 간 관계(예: 거리)를 표시할 수 있다.
- 트리와 다르게 **사이클을 허용**한다.
- 사례: 항공 노선도(인천, 김포, 청주, 광주, 김해, 울산, 제주), 지하철 노선도, 인물 관계도
- **활동 3**: 놀이공원 지도(간선에 거리 표시)에서 롤러코스터 → 이벤트 홀 최단 거리 구하기 (p.87)

#### 활동 4 — A 마을 화재 (트리로 표현) (p.88)
- 조건: 칸의 위치는 (X, Y) 좌표, 화재 발생 위치 (3, 3), 불이 번질 수 없는 칸과 번질 수 있는 칸이 있음, 불은 **1시간에 1칸**, 상하좌우로 동시에 퍼짐
- ⑴ 핵심 요소 '좌표'로 불이 번지는 과정을 트리로 표현(루트 (3, 3) → (3, 4), (3, 2) 등) ⑵ 2시간 뒤 불이 번진 칸 수 ⑶ 마을 전체로 번지는 시간
- 지도의 막힌 칸 표시는 그림이라 추출본에 없어 답은 생략한다.

### 나의 미래 꿈 — 디지털 사회의 직업 (p.89)
- 인공지능 전문가, 자율주행 자동차 개발자, 빅데이터 플랫폼 운영자 등 새 직업 등장, 로봇 개발자·소프트웨어 개발자 등 역할 강화
- 로봇 윤리학자: 인간을 위해 로봇들이 지켜야 하는 행동 규범을 만든다.
- 인공지능 전문가: 스스로 사고하고 추론하는 능력을 갖춘 컴퓨팅 시스템을 개발한다.
- 스마트팜 구축가: 인공지능, 사물 인터넷, 무인 자동화 등을 농업에 융합해 지능화된 농장을 만든다.
- UX·UI 디자이너: 사용자의 요구를 파악해 디지털 기기를 활용할 수 있는 환경을 디자인한다.
- 바이오 의약품 개발 전문가: 생명체에서 얻은 물질로 인간을 치료하는 약을 개발한다.
- 데이터 과학자: 많은 데이터를 수집·가공해 의미 있는 결과를 도출한다.
- 정보 보안 전문가: 해커 침입과 바이러스에 대비해 전산망을 보안·유지한다.
- 커리어넷에서 직업의 하는 일, 준비할 것, 관련 학과 확인

### 선택 활동 — 가장 영향력 있는 친구 찾기 (p.90~91)
- **6단계 분리 이론**: 미국의 사회학자 **스탠리 밀그램(Milgram, Stanley)**이 발표. 지구상의 모든 사람이 서로 **6단계 이내**로 연결되어 있다는 주장. 예: 아이유 - 배두나(브로커) - 톰 행크스(클라우드 아틀라스) - 케빈 베이컨(아폴로 13), **3단계**. 사회 관계망 분석에 활용
- 영향력 있는 사람 찾는 방법 (p.90)
  1. 단계1: 입력(`A C`, `A D`, `D C`, `C B` = 각 쌍이 친구)으로 친구 관계를 그래프로 표현
  2. 단계2: 모든 친구 쌍의 **친구 단계**(두 사람이 이어지기까지 걸리는 **최소** 단계)를 구함. A-B 2, A-C 1
  3. 단계3: 개인별 **친구 관계의 합**(친구 단계를 모두 더한 값). A = 2 + 1 + 1 = 4, B = 5, C = 3, D = 4
  4. 단계4: 친구 관계의 합이 **가장 작은 사람** = 가장 영향력 있는 사람 → **C, 3**

| | A | B | C | D |
|---|---|---|---|---|
| A | × | 2 | 1 | 1 |
| B | 2 | × | 1 | 2 |
| C | 1 | 1 | × | 1 |
| D | 1 | 2 | 1 | × |

- 과제 2: 6명의 친구 관계 `A B, A D, B F, D F, C F, C E, E F` (p.91)
  - 단계1 문제 분석: 현재 상태 — 6명의 친구 관계를 알고 있다 / 제약 조건 — 경로가 여러 가지면 가장 작은 값을 친구 단계로 정의
  - 단계2 문제 분해 → 단계3 핵심 요소 추출 → 단계4 모델링(그래프와 6×6 표) → 단계5 문제 해결
  - 풀이(직접 계산): 친구 관계의 합 A 10, B 8, C 9, D 8, E 9, **F 6** → 가장 영향력 있는 사람은 **F, 6**
- 스스로 평가하기: 복잡한 문제를 해결 가능한 작은 문제로 분해하고 모델링할 수 있는가? (p.91)

## 비교·정리표

### 트리 vs 그래프
| 구분 | 트리 | 그래프 |
|---|---|---|
| 표현 | 계층적 관계 | 연결 관계(노드와 간선) |
| 간선 방향 | 상위 노드 → 하위 노드로만 | 화살표로 방향성 표현 가능 |
| 사이클 | 허용하지 않음 | 허용 |
| 특별한 노드 | 루트 노드(최상위) | 없음 |
| 사례 | 폴더 구조, 조직도, 동물 분류 | 항공 노선도, 지하철 노선도, 인물 관계도 |

### 모델링 방법 3가지
| 방법 | 구조 | 쓰임 | 사례 |
|---|---|---|---|
| 표 | 행과 열 | 조건 비교·평가, 정리 | 거래 내역, 프로젝트 일정, 성적 관리, 이용권 요금, 알레르기 |
| 트리 | 계층 | 상하 관계 | 폴더, 조직도, 동물 분류, 화재 확산 |
| 그래프 | 노드+간선 | 연결 관계·거리 | 항공·지하철 노선도, 인물 관계도, 친구 관계 |

### 추상화의 세 과정
| 과정 | 하는 일 | 예제 1(로봇) 적용 |
|---|---|---|
| 문제 분해 | 작은 문제로 나눔(관계·순서 유의, 결과 종합) | 좌표 계산 / 이동 / 격자 이탈 감지 / 최종 좌표 반환 |
| 핵심 요소 추출 | 불필요한 요소 제거, 필요한 요소 추출(가장 중요한 단계) | 격자 공간, 이동 계획, 로봇 |
| 모델링 | 표·트리·그래프로 구조화 | 격자 좌표 그림 |

### 문제 분석의 세 질문
| 질문 | 예제 1 | 예제 4 |
|---|---|---|
| 현재 상태·목표 상태 | S(1,1)에 있음 → 최종 좌표 출력 | 주문 전 → 결제 금액·주문 번호 출력 |
| 요구 사항 | 이동 계획에 따른 최종 좌표 출력 | 결제 금액 안내, 주문 번호 출력 |
| 제약 조건 | 상하좌우 한 칸, 격자 밖 이동 무시 | 주문 번호 매일 0 초기화, 연속 번호 |

## 시험 함정 포인트
- 모델링은 추상화와 같은 말이 아니라 **추상화의 한 과정**이다. 추상화 = 문제 분해 + 핵심 요소 추출 + 모델링. (p.82, p.85)
- 추상화의 가장 중요한 단계는 모델링이 아니라 **핵심 요소 추출**이다. (p.83)
- 핵심 요소를 고르는 기준은 고정된 것이 아니라 **문제 해결의 목적에 따라 달라질 수 있다**. (p.83)
- 트리는 사이클을 **허용하지 않고**, 그래프는 사이클을 **허용**한다. (p.87)
- 트리에서 간선은 **상위 → 하위 노드로만** 존재한다. 상위 노드가 없는 노드가 **루트 노드**다. (p.87)
- 문제 분석에서 정의하는 것은 현재·목표 상태, 요구 사항, **제약 조건**이다(해결 방법을 정하는 단계가 아님). (p.81)
- 예제 1에서 격자를 벗어나는 이동은 오류가 아니라 **무시**한다. `R R D R D L`(3×3)의 답은 (3, 2). (p.81)
- 친구 단계는 경로가 여러 개일 때 **가장 작은 값**이고, 영향력 있는 사람은 친구 관계의 합이 **가장 작은** 사람이다(큰 사람이 아님). (p.90~91)
- 6단계 분리 이론의 발표자는 **스탠리 밀그램**이고, 아이유~케빈 베이컨 예는 6단계가 아니라 **3단계**다. (p.90)
- 해리 벡의 노선도는 지도를 더 자세히 그린 것이 아니라 **선과 기호만으로 단순화**한 것이다. (p.85)
- 컴퓨터 문제 해결 순서: 문제 분석 → 문제 분해 → 모델링 → 알고리즘 설계 → 프로그래밍 → 결과 평가 및 개선. (p.78~79)

## 핵심 용어 사전
| 용어 | 뜻 |
|---|---|
| 문제 | 해결해야 할 구체적이고 명확한 요구 사항 |
| 문제 분석 | 문제 상태, 요구 사항, 제약 조건을 정의하는 과정 |
| 현재 상태 / 목표 상태 | 문제의 출발 상태 / 해결 후 도달할 상태 |
| 요구 사항 | 문제가 해결하고자 하는 것 |
| 제약 조건 | 문제를 해결할 때 지켜야 할 조건 |
| 추상화 | 복잡한 문제를 단순화하는 과정(분해, 핵심 요소 추출, 모델링 포함) |
| 문제 분해 | 복잡한 문제를 해결하기 쉬운 작은 문제로 나누는 과정 |
| 핵심 요소 추출 | 불필요한 요소를 제거하고 필요한 요소만 뽑는 추상화의 가장 중요한 단계 |
| 모델링 | 핵심 요소를 표, 트리, 그래프 등으로 단순화·구조화하는 과정 |
| 모델 | 핵심 요소들 간의 관계를 추상적으로 표현한 모형 |
| 표 | 데이터를 행과 열로 나누어 표현하는 구조 |
| 트리 | 데이터 간 관계를 계층적으로 표현하는 구조, 사이클 불허 |
| 루트 노드 | 상위 노드가 없는 최상위 노드 |
| 그래프 | 연결 관계를 노드와 간선으로 표현하는 구조, 사이클 허용 |
| 노드 | 데이터 항목을 나타내는 도형상의 정점 |
| 간선 | 데이터의 흐름이나 관계를 나타낸 선 |
| 사이클 | 출발 노드로 다시 돌아오는 순환 구조 |
| 6단계 분리 이론 | 모든 사람이 6단계 이내로 연결되어 있다는 밀그램의 이론 |
| 친구 단계 | 두 사람이 이어지기까지 걸리는 최소 단계 |
| 친구 관계의 합 | 한 사람의 친구 단계를 모두 합한 값 |
