# Ⅲ-01 문제 분해와 모델링[cite: 1]
교과서 75-91쪽 · 정보[cite: 1]

## 학습 목표[cite: 1]
- 컴퓨터를 이용한 문제 해결 과정을 설명할 수 있다. (p.79)[cite: 1]
- 복잡한 문제를 해결 가능한 작은 문제로 분해하고 핵심 요소를 추출할 수 있다. (p.79)[cite: 1]
- 문제 해결에 필요한 데이터 간의 관계를 분석하고 모델링할 수 있다. (p.79)[cite: 1]
- 무엇을 배울까? — 생활 속 복잡한 문제를 해결하기 위해 어떻게 해야 할까? 생활 속 복잡한 문제를 찾아 단순하게 표현해 보자. / 핵심 요소: 문제 분석, 문제 분해, 핵심 요소 추출, 모델링 (p.79)[cite: 1]

## 핵심 개념[cite: 1]

### 대단원 Ⅲ 도입 — 알고리즘과 프로그래밍[cite: 1]
- 소단원 구성: 01 문제 분해와 모델링, 02 알고리즘, 03 프로그래밍의 이해, 04 제어 구조의 응용, 05 함수와 라이브러리, 06 객체지향 프로그래밍, 07 창의 융합 프로그래밍 (p.75)[cite: 1]
- 생각해 보자: 문제 분해와 모델링으로 문제 해결 모델 설계하기 / 알고리즘의 수행 과정 및 효율성 비교·분석하기 / 복잡한 문제를 프로그래밍으로 해결하기 (p.76)[cite: 1]
- **생각에 날개 달기 — 놀이공원에서의 즐거운 하루**: 성진이가 누나와 놀이공원에 가기로 했다. 우선 처음에 갈 놀이 장소를 이벤트 홀로 정하고 정문에서 이벤트 홀까지 가는 가장 빠른 길을 찾아보려 한다. 컴퓨터를 이용해 어떻게 문제 해결을 하는지 살펴보자. (p.77)[cite: 1]
  - 컴퓨터를 이용한 문제 해결 흐름: **문제 분석 → 문제 분해 → 모델링 → 알고리즘 설계 → 프로그래밍 → 결과 평가 및 개선** (p.77~78)[cite: 1]
  - 문제 분석: "목적지까지 경로가 많네" / 핵심: "분수 광장을 경유해야 해!" / 모델링: 놀이기구만 뽑아 표, 트리, 그래프로 표현 — "거리도 알 수 있어서 그래프가 좋다" (p.77)[cite: 1]
  - 알고리즘 설계: 그래프 구조에서 이벤트 홀까지의 최적 경로를 탐색한다. 그래프 구조에서 최적 경로 탐색 → 최적 경로는 **정문 → 분수 광장 → 바이킹 → 이벤트 홀** (p.77~78)[cite: 1]
  - 프로그래밍: 파이썬 언어로 알고리즘을 구현해 보자. 파이썬으로 구현. 놀이공원 안의 다른 문제 — 키 제한 조건 확인하기(조건문), 탑승 순서 알아보기(함수, "한번에 30명 탑승하는데 우린 몇 번째?"), 간식 메뉴 정하기(모델링, 알레르기) (p.78)[cite: 1]
  - 컴퓨터를 이용한 문제 해결 흐름의 마지막 단계는 결과 평가 및 개선이다. (p.78)[cite: 1]
  - 동아리 홍보 도입 만화는 79쪽에 제시되어 있다. (p.79)[cite: 1]
  - 도입 만화(동아리 홍보): 친구 관계를 정리 → 복잡하니 작은 문제로 나누기 → 불필요한 요소를 삭제하며 꼭 필요한 요소만 추출(핵심 요소) → 친구 관계를 그래프와 표 형태로 표현해 봤어. 부탁할 친구가 누군지 한눈에 알겠어. (p.79)[cite: 1]

### 1. 문제 분석[cite: 1]
- **문제**: 우리가 해결해야 할 **구체적이고 명확한 요구 사항**을 말한다. (p.80)[cite: 1]
- **문제 분석**: 문제를 명확하게 이해하고 주어진 문제 상태와 요구 사항 및 제약 조건을 정의하기 위해서 문제 분석을 수행한다. (p.80)[cite: 1]
- 문제 분석의 세 질문 (p.80)[cite: 1]
  1. 문제의 **현재 상태와 목표 상태**는 무엇인가?
  2. 문제의 **요구 사항**은 무엇인가? 문제의 요구 사항을 파악하는 것은 문제가 해결하고자 하는 것을 이해하는 것이다. (p.80)[cite: 1]
  3. 문제의 **제약 조건**은 무엇인가?
- **예제 1 — 퍼레이드 로봇** (p.80)[cite: 1]
  - 문제 상황: N × N 크기(N: 1~100)의 정사각형으로 구성된 놀이공원에서 이동 계획에 따라 움직이는 퍼레이드 로봇이 있다. 격자 공간의 크기와 이동 계획이 주어졌을 때, 퍼레이드 로봇이 도착한 최종 좌표 P를 출력하는 프로그램을 만들어 보자. 단, 로봇은 시작 좌표 S(1, 1)에서 출발하여 격자 공간을 벗어나는 이동은 무시한다. (p.80)[cite: 1]
  - 이동 명령: L 왼쪽으로 한 칸, R 오른쪽으로 한 칸, U 위로 한 칸, D 아래로 한 칸 (p.80)[cite: 1]
  - 입출력 예: 격자 3, 이동 `R R D R D L` → (3, 2) / 격자 4, 이동 `D D R R U R` → (2, 4) (p.80)[cite: 1]
  - 풀이: 현재 상태 — 로봇이 시작 좌표 S(1,1)에 있다 / 목표 상태 — 로봇이 도착한 최종 좌표를 출력 / 요구 사항 — 로봇이 이동 계획에 따라 최종적으로 도착한 좌표를 출력 / 제약 조건 — 로봇은 상(U), 하(D), 좌(L), 우(R)로 한 칸씩 이동할 수 있고 격자 공간을 벗어나는 움직임은 무시된다. (p.80)[cite: 1]
  - 추적(3×3): (1,1) →R (1,2) →R (1,3) →D (2,3) →R 무시 →D (3,3) →L (3,2) (p.80)[cite: 1]

### 2. 추상화[cite: 1]
- **추상화**: 복잡한 문제를 단순화하는 것으로 먼저 문제를 작은 단위로 분해한 후 불필요한 요소는 제거하고 꼭 필요한 핵심 요소만 뽑아내는 과정이다. (p.81)[cite: 1]
- 추상화 과정: **문제 분해 → 핵심 요소 추출 → 모델링** (p.81)[cite: 1]
- 예: 넓고 복잡한 놀이공원(추상화 전) — 넓고 복잡한 놀이공원을 롤러코스터, 지구별, 식당가, 바이킹, 정문, 자이로스윙, 판다 세상, 빨간 풍차, 아마존 급류 등 주요 놀이 시설로 표현한다. (p.81~82)[cite: 1]
- 활동 1: 우리 집에서 학교까지 이용하는 버스 노선을 추상화하려고 할 때 불필요한 요소와 필수 요소를 찾아보자. 우리 집에서 학교까지 이용하는 버스 노선을 추상화할 때 불필요한 요소로는 자전거 도로 등이, 필수 요소로는 목적지를 경유하는 버스 번호 등이 있다. (p.81~82)[cite: 1]
- 추상화와 모델링의 차이: 추상화는 문제가 지닌 복잡성을 단순화하고 중요한 특징을 강조하는 과정으로, 추상화에는 문제 분해와 핵심 요소 추출, 모델링 과정이 모두 포함된다. (p.84~85)[cite: 1]

#### ① 문제 분해 (p.82~83)[cite: 1]
- **문제 분해**: 복잡한 문제를 해결하기 쉽게 작은 문제로 나누는 과정을 문제 분해라고 한다. (p.83)[cite: 1]
- 문제 사이의 **관계나 순서에 유의**하여 작은 문제로 분해하여 먼저 해결하고, 그 **결과를 종합**하면 문제 전체를 해결할 방법을 찾을 수 있다. (p.83)[cite: 1]
- **예제 2**(예제 1 분해): 분해1 로봇의 현재 좌표를 계산하는 부분 / 분해2 이동 계획에 따라 로봇을 이동시키는 부분 / 분해3 격자 공간을 벗어난 이동을 감지하는 부분 / 분해4 로봇의 최종 도착 좌표를 반환하는 부분 (p.83)[cite: 1]

#### ② 핵심 요소 추출 (p.82~83)[cite: 1]
- 추상화의 가장 중요한 단계로 문제 해결과 관련 없는 불필요한 요소를 제거하고 꼭 필요한 핵심 요소를 추출하는 과정이다. 이를 위해서는 여러 정보와 사실을 구분하기 위한 기준이 있어야 하며 그 기준은 문제 해결의 목적에 따라 달라질 수 있다. (p.83)[cite: 1]
- **예제 3**(예제 1 핵심 요소): 3×3 크기의 격자 공간, 이동 계획, 퍼레이드 로봇 (p.83)[cite: 1]

#### 예제 4 — 카페 키오스크 프로그램 (p.83~84)[cite: 1]
- 문제 상황: 소영이는 카페를 운영하는 어머니께 도움을 드리려고 키오스크 프로그램을 만들려고 한다. 손님이 메뉴와 수량을 선택하면 결제 금액을 알려 주고, 주문 후 주문 번호를 출력해 주는 프로그램이다. 단, 주문 번호는 매일 아침 0으로 초기화하며 연속 번호를 사용한다. 예를 들어 첫 번째 주문은 1번, 두 번째 주문은 2번이다. (p.83~84)[cite: 1]
- 현재 상태: 주문을 받지 않은 상태 / 목표 상태: 사용자로부터 주문을 받아 결제 금액과 주문 번호를 출력한 상태 (p.84)[cite: 1]
- 세 개로 분해: 분해된 문제 1 메뉴·수량·금액 → 분해된 문제 2 결제 금액 출력 → 분해된 문제 3 주문 번호 출력 (p.84)[cite: 1]
- 핵심 요소 <보기>: 메뉴명, 대기 시간, 주문 번호, 결제 방식, 고객 이름, 메뉴 가격, 주문 금액, 수량, 신용 카드, 포장, 배달 → 교과서 풀이에 나온 핵심 요소: 메뉴(메뉴명·가격)·수량, 주문 금액, 주문 번호 (p.84)[cite: 1]
- 화면 예: 초코 라테 3500원, 카페모카 4500원, 코코아 2500원 (3500×1 + 4500×1 + 2500×1 = 총액 10500원), 주문 번호 138 (p.84)[cite: 1]
- 예제 4의 핵심 요소로 '메뉴(메뉴명·가격)·수량, 주문 금액, 주문 번호'를 제시했으나 교과서 풀이의 핵심 요소 표기와 정확히 대응하는지 모호함 (p.84)[cite: 1]

### 3. 모델링 (p.84~88)[cite: 1]
- 분해한 문제에서 추출한 핵심 요소들을 이해하기 쉽게 표와 트리, 그래프 등으로 단순화하거나 구조화하는 과정을 의미한다. 추상화의 한 과정인 모델링 작업을 통해서 만들어진 모델은 데이터 간의 관계나 흐름을 쉽게 이해할 수 있어 문제를 효율적으로 해결하는 데 도움이 된다. (p.84~85)[cite: 1]
- **모델(model)**: 문제 해결에 필요한 핵심 요소들 간의 관계를 추상적으로 표현한 모형이다. (p.85)[cite: 1]
- 해결하려는 문제의 특성에 따라 **적합한 모델링 방법을 선택**할 수 있어야 한다. (p.85)[cite: 1]
- 사례 — **런던 지하철 노선도**: 1908년에 제작된 영국 런던의 지하철 노선도는 지도 위에 지하철역과 노선을 표현하였다. 한꺼번에 너무 많은 정보를 전달하고 있어 복잡하다는 문제가 있었다. 이후 **해리 벡(Beck, Harry)**이 선과 기호만으로 지하철 노선도를 단순하게 표현하여, 한눈에 목적지와 방향을 볼 수 있도록 바꾸었다. (p.85)[cite: 1]

#### ① 표 (p.85~86)[cite: 1]
- 데이터를 가로축(행)과 세로축(열)으로 나누어 표현하는 구조로 표를 이용하면 주어진 조건들을 비교·평가하거나 복잡한 문제들을 보기 쉽게 정리할 수 있다. (p.86)[cite: 1]
- 사례: 거래 내역 관리, 프로젝트 일정 관리, 학생 성적 관리 (p.86)[cite: 1]
- 놀이공원 이용권별 요금을 표 형태로 모델링하기: 주간권은 대인 56,000원, 청소년 47,000원, 소인·경로 44,000원이고, 야간권(16시~)은 대인 46,000원, 청소년 40,000원, 소인·경로 37,000원이다. (p.86)[cite: 1]
- **활동 2 — 식품 알레르기 표** (p.85~86)[cite: 1]
  - 메뉴(알레르기 유발 물질): 구슬 아이스크림(①, ②, ⑤), 닭강정(②, ③, ④, ⑤, ⑦, ⑧, ⑨, ⑩, ⑪), 추로스(②, ④, ⑤), 치즈 핫도그(①, ②, ④, ⑤, ⑥, ⑦, ⑧, ⑨, ⑩, ⑪) (p.85)[cite: 1]
  - 식품 알레르기 정보: ① 난류, ② 우유, ③ 땅콩, ④ 대두, ⑤ 밀, ⑥ 돼지고기, ⑦ 토마토, ⑧ 아황산염, ⑨ 닭고기, ⑩ 쇠고기, ⑪ 조개류 (p.85)[cite: 1]
  - 풀이: 모든 메뉴에 포함된 알레르기 물질은 **우유, 밀** / 땅콩, 돼지고기, 조개류에 알레르기가 있는 사람이 먹을 수 있는 음식은 **구슬 아이스크림, 추로스** (p.85~86)[cite: 1]
  - 활동 2의 풀이(모든 메뉴 포함 물질: 우유·밀, 땅콩·돼지고기·조개류 알레르기 환자가 먹을 수 있는 음식: 구슬 아이스크림·추로스)를 교과서 본문 근거 없이 제시한 것으로 보이는 점 (p.85~86)[cite: 1]

#### ② 트리 (p.86~87)[cite: 1]
- 데이터 간 관계를 계층적으로 표현하기에 적합한 구조이다. 나무처럼 뿌리에서 가지가 뻗어 나가는 모습을 거꾸로 표현한 것으로 상위 노드가 없는 최상위 노드를 루트 노드(root node)라고 하고 그 밑에 하위 노드를 연결한 형태를 가진다. 상위 노드에서 하위 노드로만 간선이 존재하고 노드 간 사이클(순환)은 허용하지 않는다. (p.86)[cite: 1]
- 사례: 컴퓨터 폴더 구조, 조직도, 동물의 분류(동물 → 육식 동물[사자, 호랑이], 초식 동물[기린, 얼룩말]) (p.86~87)[cite: 1]
- **노드(node)**: 데이터 항목을 나타내는 것으로 도형상의 정점을 나타낸다. (p.86)[cite: 1]
- **간선(edge)**: 데이터의 흐름이나 관계를 선으로 나타낸 것이다. (p.86)[cite: 1]
- **사이클(cycle)**: 어떤 특정 노드에서 출발하여 간선과 노드들을 지나 다시 처음에 출발했던 특정 노드로 되돌아오는 순환 구조를 말한다. (p.86)[cite: 1]

#### ③ 그래프 (p.87)[cite: 1]
- 데이터 간 연결 관계를 노드와 간선으로 표현하는 구조이다. 화살표를 이용하여 데이터의 방향성을 표현할 수 있고, 간선 위에 데이터 간의 관계를 표시할 수도 있다. (p.87)[cite: 1]
- 트리와 다르게 어떤 특정 노드에서 출발하여 간선을 지나 다시 출발했던 노드로 돌아오는 순환 구조(사이클)를 허용한다. (p.87)[cite: 1]
- 사례: 항공 노선도, 지하철 노선도, 인물 관계도 (p.87)[cite: 1]
- 항공 노선도의 그래프 구조에는 인천, 청주, 광주, 김해, 울산, 김포, 제주가 표현되어 있다. (p.87)[cite: 1]
- **활동 3**: 놀이공원 지도(간선에 거리 표시)에서 롤러코스터 → 이벤트 홀 최단 거리 구하기 (p.87)[cite: 1]

#### 활동 4 — A 마을 화재 (p.88)[cite: 1]
- 조건: 한 칸의 위치는 (X, Y) 좌표, 화재 발생 위치는 (3, 3), 불이 번질 수 없는 칸과 불이 번질 수 있는 칸이 있음, 불은 1시간에 1칸 이동하며 상하좌우로 동시에 퍼져 나간다. (p.88)[cite: 1]
- ⑴ 핵심 요소인 '좌표'로 불이 번지는 과정을 트리 형태로 표현 ⑵ 2시간 뒤 불이 번진 칸 수 ⑶ 마을 전체로 번지는 시간 (p.88)[cite: 1]
- 활동 4에서 지도의 막힌 칸 표시가 추출본에 없어 답을 생략한다고 한 부분 (p.88)[cite: 1]

### 선택 활동 — 가장 영향력 있는 친구 찾기 (p.90~91)[cite: 1]
- **6단계 분리 이론**: 미국의 사회학자 **스탠리 밀그램(Milgram, Stanley)**이 발표한 이론으로 지구상의 모든 사람이 서로 6단계 이내로 연결되어 있다고 주장한다. 특정인과 모든 사람과의 관계를 파악하는 사회 관계망 분석에 활용될 수 있다. (p.90)[cite: 1]
- 영향력 있는 사람 찾는 방법 (p.90)[cite: 1]
  1. 단계1: 주어진 입력으로 친구 관계를 그래프로 표현한다.
  2. 단계2: 모든 친구 쌍에 대한 친구 단계(최소 단계)를 구한다.
  3. 단계3: 개인별 친구 관계의 합(친구 단계를 모두 합한 값)을 구한다.
  4. 단계4: 친구 관계의 합이 가장 작은 사람과 값을 찾는다. → C, 3 (p.90)[cite: 1]
- 과제 2: 6명의 친구 관계는 A B, A D, B F, D F, C F, C E, E F이다. (p.90~91)[cite: 1]
  - 문제 분석(단계1~4): 현재 상태 — 6명의 친구 관계를 알고 있다 / 제약 조건 — 친구 단계를 구하는 경로가 여러 가지일 때는 가장 작은 값을 '친구 단계'라고 정의한다. (p.91)[cite: 1]
  - 풀이(직접 계산): 친구 관계의 합 A 10, B 8, C 9, D 8, E 9, F 6 → F, 6 (과제 2의 풀이(친구 관계의 합 A 10, B 8, C 9, D 8, E 9, F 6 → F, 6)를 직접 계산이라고 밝혔으나 교과서에 답이 제시되어 있지 않은 점) (p.90~91)[cite: 1]
- 스스로 평가하기: 복잡한 문제를 해결 가능한 작은 문제로 분해하고 모델링할 수 있는가? (p.91)[cite: 1]

## 시험 함정 포인트[cite: 1]
- 모델링은 추상화의 한 과정이며, 추상화에는 문제 분해, 핵심 요소 추출, 모델링 과정이 모두 포함된다. (p.81, p.84~85)[cite: 1]
- 추상화의 가장 중요한 단계는 모델링이 아니라 **핵심 요소 추출**이다. (p.83)[cite: 1]
- 핵심 요소를 추출하기 위한 기준은 문제 해결의 목적에 따라 달라질 수 있다. (p.83)[cite: 1]
- 트리는 노드 간 사이클을 허용하지 않으며, 그래프는 순환 구조(사이클)를 허용한다. (p.86~87)[cite: 1]
- 트리에서 간선은 상위 노드에서 하위 노드로만 존재하며, 상위 노드가 없는 최상위 노드를 루트 노드라고 한다. (p.86)[cite: 1]
- 문제 분석 단계에서 정의하는 것은 현재·목표 상태, 요구 사항, 제약 조건이다. (p.80)[cite: 1]
- 예제 1에서 격자 공간을 벗어나는 이동은 오류가 아니라 무시된다. (p.80)[cite: 1]
- 6단계 분리 이론의 발표자는 스탠리 밀그램이며, 지구상의 모든 사람이 서로 6단계 이내로 연결되어 있다는 이론이다. (p.90)[cite: 1]
- 해리 벡은 런던 지하철 노선도를 선과 기호만으로 단순하게 표현하여 한눈에 목적지와 방향을 볼 수 있도록 바꾸었다. (p.85)[cite: 1]
- 컴퓨터를 이용한 문제 해결 흐름은 문제 분석 → 문제 분해 → 모델링 → 알고리즘 설계 → 프로그래밍 → 결과 평가 및 개선 순서이다. (p.77~78)[cite: 1]
