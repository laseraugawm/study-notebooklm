## 핵심 개념

### 도입 — 영화 찾기
- 개봉일, 누적 관객 수, 예매 순위, 가까운 영화관 등 찾는 방법이 다양하다. 예매한 자리(G열 7번, 8번, 9번) 찾기 → "이게 바로 프로그램에서 **정렬과 탐색**의 힘이야!" (p.92)

### 1. 알고리즘의 이해
- **알고리즘**: 문제 해결을 위한 방법이나 절차. 예: 키 제한이 있는 놀이기구 탑승 여부를 판단하는 알고리즘 (p.93)
- 알고리즘의 흐름: **입력**(필요한 데이터 값을 입력) → **처리**(입력 데이터를 조건에 맞게 처리) → **출력**(처리된 결과를 나타냄) (p.93)
- 알고리즘은 컴퓨터가 수행할 수 있도록 **명령이나 연산이 명확**해야 한다. (p.93)

#### ① 알고리즘 설계 (p.93)
- **알고리즘 설계**: 문제 해결을 위한 구체적인 방법을 기술하는 것. 문제의 특성과 요구 사항을 고려해 다양한 구조로 설계
- 세 가지 구조
  1. **순차 구조**: 순서대로 명령을 실행한다. 예: 입장 → 바이킹 → 롤러코스터 → 회전목마 → 퇴장
  2. **선택 구조**: 주어진 조건에 따라 실행하는 명령이나 순서가 달라진다. 예: 키가 140cm 이상인가? 참 → 롤러코스터 탑승
  3. **반복 구조**: 주어진 조건에 따라 특정 명령을 반복적으로 실행한다. 예: 앞에 대기줄이 있는가? 참 → 기다린다(반복), 거짓 → 놀이기구 탑승
- 둘 이상의 제어 구조를 **겹쳐서** 설계할 수도 있다.

#### ② 알고리즘의 표현 (p.94)
- **자연어**: 특정한 형식 없이 말이나 글로 표현
- **의사 코드**: 프로그램 코드를 흉내 내어 표현
- **순서도**: 정해진 기호를 이용하여 표현
- 순서도 기호의 의미: 시작과 끝 / 조건식 / 실행 흐름 / 데이터의 입력과 출력 / 데이터의 처리
- 예: 나이로 놀이공원 입장료 계산
  - 자연어: 나이를 입력받는다. 9세 미만이면 3만 원, 9세 이상 18세 미만이면 4만 원, 18세 이상이면 5만 원. 입장료를 출력한다.
  - 의사 코드
    ```
    나이 입력
    만약 나이 ＜ 9세
        입장료 = 3만 원
    아니면
        만약 나이 ＜ 18세
            입장료 = 4만 원
        아니면
            입장료 = 5만 원
    입장료 출력
    ```
  - 순서도: 시작 → 나이 입력 → 나이＜9세? 참: 입장료=3만 원 / 거짓: 나이＜18세? 참: 4만 원, 거짓: 5만 원 → 입장료 출력 → 끝

#### ③ 알고리즘의 효율성 분석 (p.95)
- **효율적인 알고리즘**: 실행해 결과가 나올 때까지 **기억 장소의 사용량이 적고 수행 시간이 짧은** 알고리즘
- 효율적인 알고리즘의 조건: 작업량이 적고 수행 시간이 짧다 / 기억 장소의 사용량이 적다. 두 조건을 동시에 만족하면 가장 효율적이지만, 둘 다 어렵다면 **수행 시간이 짧은** 알고리즘을 작성하는 것이 좋다.
- 같은 입력과 출력이라도 방법에 따라 수행 시간이 달라진다 → 효율적인 알고리즘을 설계·선택해야 한다.
- 예: 1부터 100까지의 합
  - 방법 1: 1 + 2 + 3 + … + 100 = 5050. 단순하지만 더하는 수가 많아질수록 **덧셈 횟수가 증가**해 수행 시간 증가
  - 방법 2: 오름차순과 내림차순으로 정렬한 수를 서로 더하면 모두 101 → `101 × 100 ÷ 2 = 5050`. 덧셈, 곱셈, 나눗셈을 **한 번씩만** 수행하므로 **일정한 수행 시간**
- 활동 5 — 'Coding for Carrots'(https://bit.ly/CodingDoodle): 토끼가 당근을 모두 모으는 퍼즐. 4개 명령어(앞으로 한 칸 이동, 오른쪽으로 90도 회전, 왼쪽으로 90도 회전, 반복[횟수 변경 가능])로 1~6단계를 **가장 적은 수의 블록**으로 해결 (p.95)
- 활동 6 — **스마트 그늘막**(사물 인터넷 기술): 실시간 기상 상황을 확인해 스스로 펼치고 접음. 기온, 풍량, 일출·일몰 시간에 따라 자동 작동, 강풍 등에 신속 대처, 별도 인력 불필요 (p.96)
  - 자연어: ① 시각, 기온 입력 ② 오전 9시~오후 6시 사이면 LED를 끈다 ③ 그 시간이면서 기온 20℃ 이상이면 그늘막을 펼친다 ④ 그 시간이면서 20℃ 미만이면 접는다 ⑤ 오후 6시~오전 9시 사이면 그늘막을 접고 LED를 켠다.
  - 의사 코드(교과서 제시 부분): `만약 오전 9 <= 시각 < 18` → LED OFF / 아니면 → 그늘막 접기, LED ON
  - 순서도 조건: `9 ≤ 시각 < 18`, 그 안에서 `기온 ≥ 20℃`

### 2. 정렬 알고리즘
- **정렬**: 수많은 데이터를 특정 기준에 따라 순서대로 나열하는 것. 원하는 데이터를 빠르게 찾게 하고 일을 효율적으로 처리하도록 돕는다. 예: 출석부(가나다순), 인터넷 쇼핑몰(낮은 가격순, 판매순) (p.97)
- **오름차순**: 작은 것부터 큰 순서(0→9, A→Z, ㄱ→ㅎ) / **내림차순**: 큰 것부터 작은 순서(9→0, Z→A, ㅎ→ㄱ) (p.97)
- 정렬의 활용 그림: 대기 시간 오름차순 놀이공원 앱, 최근 도착한 메시지순 채팅방 목록, 낮은 가격순 쇼핑몰 (p.97)
- 활동 7: 알람 설정 앱, 일기 예보, 해수욕장 검색 결과에서 정렬이 사용된 곳과 정렬 기준 찾기 (p.97)

#### ① 정렬 알고리즘의 종류 (p.98~99)
- 대표적인 방법: **버블 정렬(bubble sort)**, **선택 정렬(selection sort)**
- **버블 정렬**: **인접한 두 개의 데이터**를 비교하여 자리를 교환하는 방법. 이름은 교환되는 모습이 거품이 수면 위로 올라오는 듯해서 붙여졌다. (p.98)
  - [5, 2, 7, 3] 오름차순
    - 단계 1: 5와 2 교환 → 2 5 7 3 / 5와 7 그대로 / 7과 3 교환 → 2 5 3 7 → 네 번째 위치에 가장 큰 값 7 고정
    - 단계 2: 2와 5 그대로 / 5와 3 교환 → 2 3 5 7 → 세 번째 위치에 5 고정
    - 단계 3: 2와 3 그대로 → 두 번째 위치에 3 고정 → 정렬 완료
- **선택 정렬**: (오름차순) 첫 번째 위칫값을 **기준**으로 정하고, 나머지 데이터를 모두 비교해 **가장 작은 데이터**를 찾아 기준 위치의 데이터와 교환 (p.99)
  - [5, 2, 7, 3] 오름차순
    - 단계 1: 기준 5, 나머지(2, 7, 3) 중 최솟값 2 → 교환 → 2 5 7 3, 첫 번째에 2 고정
    - 단계 2: 기준 5, (7, 3) 중 최솟값 3 → 교환 → 2 3 7 5, 두 번째에 3 고정
    - 단계 3: 기준 7, (5) 최솟값 5 → 교환 → 2 3 5 7 → 정렬 완료
- 탐색: [5, 2, 7, 3]을 버블·선택 정렬로 내림차순 정렬하기 → 결과 7 5 3 2 (p.99)

#### ② 효율성 비교 (p.100~101)
- 같은 데이터를 오름차순 정렬할 때 버블 정렬과 선택 정렬의 **비교 횟수는 같지만 교환 횟수가 다르다**.
- [8, 4, 2, 1] 오름차순
  - **버블 정렬**: 비교와 동시에 교환 → 비교 **6회**, 교환 **6회**
  - **선택 정렬**: 비교 **6회**, 교환 **2회**(8↔1, 4↔2) → 버블 정렬보다 정렬 속도가 빠르다.
- 버블 정렬: 인접한 두 데이터를 비교해 순서를 바꾸므로 **최악의 경우 모든 데이터의 쌍을 교환**해야 한다.
- 선택 정렬: 매 단계 최솟값 또는 최댓값을 찾은 후에야 교환하므로 버블 정렬보다 **교환 횟수가 적어 더 빠르다**.
- 두 정렬 모두 n개의 데이터에서 시작해 아직 정렬되지 않은 데이터의 크기를 하나씩 줄여 나간다.
- 활동 8: VisuAlgo(https://visualgo.net/en/sorting?slide=1)에서 정렬 알고리즘 종류 선택 후 [Sort]로 수행 과정 비교 (p.101)

### 3. 탐색 알고리즘
- **탐색**: 여러 개의 데이터 중에서 원하는 데이터를 찾는 과정. 예: 연락처 검색, 내비게이션 빠른 길 찾기, 도서관에서 책 찾기 (p.102)
- 활동 9: 1~30 사이 수 맞히기 게임(추측이 큰지 작은지 알려 줌). 몇 번 만에 맞혔나, 더 빨리 맞히려면? (p.102)

#### ① 탐색 알고리즘의 종류 (p.103~104)
- 선형 구조에서 쓰는 대표적인 탐색: **순차 탐색(linear search)**, **이진 탐색(binary search)**
- **순차 탐색**: 나열된 데이터를 **처음부터 차례대로** 비교하며 찾는 방법, **가장 단순한** 탐색 알고리즘. **적은 양**의 데이터 탐색에 유리 (p.103)
  - 예: [10, 20, 30, 40, 50, 60, 70]에서 50 → 10, 20, 30, 40과 비교 후 다섯 번째 값 50에서 종료(5단계)
- **이진 탐색**: 나열된 데이터의 **중앙**에 있는 데이터를 기준으로 찾는 데이터가 왼쪽에 있는지 오른쪽에 있는지 판단하며 탐색 (p.104)
  - L: 가장 왼쪽 위치, R: 가장 오른쪽 위치, M: 가운데 위치, `M = (L + R) ÷ 2` (소수점 이하는 버림)
  - 이진 탐색을 하기 전에 데이터를 **정렬**해야 한다.
  - 예: 같은 7개에서 50 → 단계 1 '50 > 중앙값(40)'이므로 오른쪽 탐색 → 단계 2 '50 < 중앙값(60)'이므로 왼쪽 탐색 → 단계 3 '50 = 중앙값(50)'이므로 종료(3단계)
- 활동 10: 시뮬레이션(https://www.cs.usfca.edu/~galles/visualization/Search.html)에서 찾을 값 입력 → 탐색 알고리즘 선택 → 과정 확인. 데이터 크기 Small 32개, Large 180개. 0~31의 32개 데이터는 오름차순 정렬, 접속마다 바뀔 수 있음 (p.103)

#### ② 효율성 비교 (p.104)
- 순차 탐색: **정렬되지 않은 데이터나 적은 수의 데이터**에 효과적. 찾는 데이터가 **마지막**에 있거나 데이터 수가 많으면 시간이 길어져 효율성이 떨어진다.
- 이진 탐색: 탐색할 데이터의 수를 **절반으로** 줄여 나가므로 순차 탐색보다 빠르다. 하지만 탐색 전에 **최소한 한 번은 데이터를 정렬**해야 하는 불편함이 있다.
- 활동 11: 가나다순 정렬된 [귤, 딸기, 망고, 바나나, 사과, 키위, 포도] (p.104)
  - 풀이: 순차 탐색 — 가장 빨리 찾는 것 귤, 가장 늦게 찾는 것 포도 / 이진 탐색 — 가장 빨리 찾는 것 바나나(첫 중앙값), 가장 늦게(3번째) 찾는 것 귤, 망고, 사과, 포도

### 정보로 통하는 세상 — 보물찾기 모험 (p.105)
- 정글 지도는 각 지점의 연결 관계를 표현한 **그래프** 모양. 보물이 어디 있는지 모르므로 모든 지점을 방문해 확인해야 한다. 그래프에서 탐색 순서를 정하면 그 순서대로 순차적으로 탐색할 수 있다.
- 방법 1 — 현재 위치에서 **가까운 곳부터**, 아직 방문하지 않은 주변의 모든 장소를 차례로 방문: 탐색 순서 A → B → C → D → E → F, 보물이 있는 F에 **6번째** 방문
- 방법 2 — 특정한 길을 선택해 **그 길 끝까지 최대한 깊이** 탐험하고 막다른 길이면 되돌아와 다른 길 탐색: 탐색 순서 A → B → C → E → F → D, F에 **5번째** 방문

### 선택 활동 1 — 택배 기사를 도와주자! (p.106)
- 건물 번호 택배 5개가 `8, 3, 7, 4, 1` 순서로 들어옴 → 들어온 순서대로 배달하면 동선이 비효율적
- 건물 번호를 오름차순 정렬(풀이)
  - 버블 정렬: 단계 1 `3 7 4 1 8` → 단계 2 `3 4 1 7 8` → 단계 3 `3 1 4 7 8` → 단계 4 `1 3 4 7 8`
  - 선택 정렬: 단계 1 `1 3 7 4 8`(8↔1) → 단계 2 `1 3 7 4 8`(기준 3이 최솟값, 교환 없음) → 단계 3 `1 3 4 7 8`(7↔4) → 단계 4 `1 3 4 7 8`
- 스스로 평가하기: 버블 정렬, 선택 정렬을 이용하여 실생활의 간단한 데이터를 정렬할 수 있다.

### 선택 활동 2 — 참가 번호를 찾아라! (p.107)
- 팀 명단(입력 순): 라온 58, 페퍼민트 24, 공상가들 5, 옥탑방 65, 미르 11, 별똥별 1, 차차차 72, 선물 상자 86, 놀라운 밴드 37, 댄싱 머신 99
- 1. 순차 탐색으로 '놀라운 밴드' 찾기 → 풀이: **9번** 만에
- 2. 팀 이름 오름차순 정렬(공상가들, 놀라운 밴드, 댄싱 머신, 라온, 미르, 별똥별, 선물 상자, 옥탑방, 차차차, 페퍼민트) 후 이진 탐색 → 풀이: 첫 중앙값 미르(5번째) → 왼쪽 → 중앙값 놀라운 밴드, **2번** 만에
- 3. 최대 탐색 횟수(풀이): 5팀 — 순차 5, 이진 3 / 10팀 — 순차 10, 이진 4 / 20팀 — 순차 20, 이진 5
- 스스로 평가하기: 순차 탐색과 이진 탐색의 특징을 이해하고 효율성을 비교·분석할 수 있다.

| 오름차순 1단계 후 고정 | 마지막 위치에 가장 큰 값 | 첫 위치에 가장 작은 값 |

| 수행 시간 | 증가 | 일정 |

## 시험 함정 포인트
- 버블 정렬과 선택 정렬은 같은 데이터에서 **비교 횟수가 같고 교환 횟수가 다르다**. 비교 횟수가 다르다고 하면 틀린다. (p.100)
- 버블 정렬은 '가장 작은 값을 찾아 교환'이 아니라 **인접한 두 데이터**를 비교·교환한다. 최솟값을 찾아 기준과 교환하는 것은 **선택 정렬**이다. (p.98~99)
- 오름차순 버블 정렬의 1단계가 끝나면 **가장 큰 값이 맨 뒤**에, 선택 정렬의 1단계가 끝나면 **가장 작은 값이 맨 앞**에 고정된다. (p.98~99)
- 선택 정렬이 버블 정렬보다 빠른 이유는 비교가 적어서가 아니라 **교환이 적어서**다. (p.100)
- 이진 탐색은 **정렬된 데이터**에서만 쓸 수 있다. 정렬되지 않은 데이터에는 순차 탐색이 효과적이다. (p.104)
- 이진 탐색의 가운데 위치는 `M = (L + R) ÷ 2`이고 **소수점 이하는 버린다**. (p.104)
- 순차 탐색은 **적은 양**의 데이터에 유리하다(많은 데이터에 유리한 것이 아님). (p.103)
- 효율적인 알고리즘은 수행 시간이 짧고 **기억 장소 사용량도 적은** 것이며, 둘 다 어려우면 **수행 시간이 짧은** 쪽을 택한다. (p.95)
- 1~100 합의 방법 2는 수가 커져도 **수행 시간이 일정**하다. (p.95)
- 의사 코드는 순서도가 아니라 **프로그램 코드를 흉내 낸** 표현이다. 정해진 **기호**를 쓰는 것이 순서도다. (p.94)
- 보물찾기에서 가까운 곳부터 방문하면 F는 **6번째**, 한 길을 끝까지 깊이 가면 **5번째**다. (p.105)
- 입장료 예에서 9세는 3만 원이 아니라 **4만 원**(9세 이상 18세 미만), 18세는 **5만 원**이다. (p.94)

## 핵심 용어 사전
| 용어 | 뜻 |
|---|---|
| 알고리즘 | 문제 해결을 위한 방법이나 절차 |
| 알고리즘 설계 | 문제 해결을 위한 구체적인 방법을 기술하는 것 |
| 순차 구조 | 순서대로 명령을 실행하는 구조 |
| 선택 구조 | 조건에 따라 실행 명령이나 순서가 달라지는 구조 |
| 반복 구조 | 조건에 따라 특정 명령을 반복 실행하는 구조 |
| 자연어 | 형식 없이 말이나 글로 알고리즘을 표현 |
| 의사 코드 | 프로그램 코드를 흉내 내어 알고리즘을 표현 |
| 순서도 | 정해진 기호로 알고리즘을 표현 |
| 효율적인 알고리즘 | 기억 장소 사용량이 적고 수행 시간이 짧은 알고리즘 |
| 정렬 | 데이터를 특정 기준에 따라 순서대로 나열 |
| 오름차순 | 작은 것부터 큰 순서로 나열 |
| 내림차순 | 큰 것부터 작은 순서로 나열 |
| 버블 정렬 | 인접한 두 데이터를 비교해 자리를 교환하는 정렬 |
| 선택 정렬 | 기준 위치와 나머지 중 최솟값을 찾아 교환하는 정렬 |
| 탐색 | 여러 데이터 중 원하는 데이터를 찾는 과정 |
| 순차 탐색 | 처음부터 차례대로 비교하는 가장 단순한 탐색 |
| 이진 탐색 | 중앙값을 기준으로 왼쪽·오른쪽을 판단하며 절반씩 줄이는 탐색 |
| L / R / M | 탐색 범위의 가장 왼쪽 / 가장 오른쪽 / 가운데 위치 |
| 스마트 그늘막 | 사물 인터넷으로 기상 상황에 맞게 스스로 펼치고 접는 그늘막 |
