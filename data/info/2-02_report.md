# Ⅱ-02 디지털 데이터 암호화
교과서 48-53쪽 · 정보

## 학습 목표
- 디지털 데이터 암호화의 개념과 암호화·복호화 과정을 설명할 수 있다. (p.48)
- 데이터 암호화 활용 사례로 암호화의 중요성과 필요성을 이해할 수 있다. (p.48)
- 무엇을 배울까? — 내 디지털 정보를 어떻게 안전하게 지키지? 디지털 데이터를 암호화하는 과정을 알아보자. / 학습 요소: 암호화, 복호화, 암호문, 키 (p.48)

## 핵심 개념

### 도입 — 디지털 데이터 암호화의 필요성
- 도입 질문: 카드 번호에 비밀번호 앞자리까지 괜찮을까? / 서버 운영자는 내 비밀번호를 그대로 저장할까? / 실물 화폐가 아닌 디지털 화폐를 어떻게 안전하게 전송하지? / 디지털 그림의 소유권을 어떻게 증명하지? (p.48)

### 1. 디지털 데이터 암호화의 이해
- **디지털 데이터 암호화**: 권한이 없는 사람이 데이터를 알아볼 수 없게 변환하는 기술 (p.48)
- 두 과정으로 이루어진다. (p.48)
  - **암호화(encryption)**: 평문 → 암호문
  - **복호화(decryption)**: 암호문 → 평문
- **평문**: 누구나 읽을 수 있는 암호화되지 않은 데이터 (p.48)
- 중요하고 민감한 데이터를 암호문으로 바꿔 기억 장치에 저장하거나 전송함으로써 데이터를 효율적으로 관리하고 보호할 수 있다. (p.48)
- **암호화의 효율**: 보안 위협을 줄이고, 데이터 유출로 인한 복구에 소요되는 컴퓨팅 자원을 절약할 수 있다. (p.48)
- 암호화와 복호화는 **키(key)와 암호 알고리즘**으로 구성된다. (p.48)
  - **암호화 키**: 암호 알고리즘 내에서 평문을 암호문으로 변경할 때 사용하는 문자열
  - **올바른 복호화 키를 가진 사람만** 암호문을 해독할 수 있으므로 **키 관리가 매우 중요**하다.
  - 암호 알고리즘에 따라 암호화와 복호화에서 같은 키를 쓰기도, 다른 키를 쓰기도 한다.
- **현대 암호에서 키의 구분** (p.48)
  - 암호화 키 = 복호화 키 → **대칭키 암호화**
  - 암호화 키 ≠ 복호화 키 → **공개키 암호화**
- 암호화·복호화 과정 그림 예: 비밀번호 "2020"(평문) → 암호화 → 암호문 "6EB8863CE399A2" → 복호화 → "2020". 키가 없는 사람은 "무슨 말이지?" (p.48)
- **카이사르 알고리즘의 암호화, 복호화 과정** (p.48)
  - 암호화 알고리즘: 키(key)값만큼 알파벳을 이동한다. 암호화 키 key = 3 → 평문 `LOVE` → 암호문 `ORYH`
  - 복호화 알고리즘: 키(key)값만큼 알파벳을 **반대로** 이동한다. 복호화 키 key = 3 → `ORYH` → `LOVE`
  - 카이사르 암호 알고리즘은 알파벳을 키만큼 이동한 다른 알파벳으로 **치환**하여 암호화한다.

### 2. 암호화 활용 사례
- 암호 기술은 정보를 숨기려는 사람들과 그 정보를 풀려는 사람들로 인해 계속 발전·진화하고 있다. (p.49)

#### ① 고대·근대 암호화 (p.49)
- 목적: 적군으로부터 아군의 정보(문자)를 보호
- 주로 사용한 방식
  - **전치 암호**: 평문의 문자를 **자리 바꿔** 암호화
  - **치환 암호**: 평문의 문자를 **다른 문자로 대체**
- 근대 암호는 복잡한 기계 장치로 전치 암호와 치환 암호를 서로 **혼합**해 문자를 치환하고 재배열하는 방식으로 발전했다.
- 사례
  1. **고대 암호 - 스키테일 암호(전치 암호)**: 굵기와 길이가 같은 스키테일(나무 막대기)을 송신자와 수신자가 나누어 가진다. 송신자가 가늘고 긴 양피지 리본을 막대기 위에서 아래로 감아 옆으로 메시지를 적어 암호화, 수신자가 암호문 리본을 돌려 복호화. 예: 평문 `Secret Message` → 암호문 `Stse acMgreees` (p.49)
  2. **고대 암호 - 카이사르 암호(치환 암호)**: 평문의 문자를 키만큼 평행 이동한 문자로 암호화하고, 암호문을 키만큼 반대로 평행 이동해 복호화. 예: key = 3, 평문 `SECRET` → 암호문 `VHFUHW` (p.49)
  3. **근대 암호 - 에니그마**: 제2차 세계 대전에 쓰인 **독일의 기계식 암호기**. 키보드로 문자 입력 → 배전반에 연결된 문자로 1차 치환 → 2차로 회전자들이 알파벳을 치환 → 암호 문자가 발광판에 출력 (p.49)
     - **회전자**: 입력 문자 26개와 치환되는 출력 문자 26개를 연결해 주는 회전판. 회전자 1개는 경우의 수 676개(= 26 × 26)가 발생. 그림에는 회전자 3개. (p.49)

#### ② 현대 암호화 (p.50)
- 컴퓨팅 시스템과 통신 기술의 발달로 **컴퓨터 프로그램 기반**의 암호 기술 등장 (p.50)
- 용도: 기업이나 개인의 디지털 정보를 보호, 디지털 정보의 **소유를 증명** (p.50)
- 사례: 패스워드 암호화, 디지털 서명, HTTPS 암호화 (p.50)
- 참고 — **공개키 암호화**: 암호화 키와 복호화 키가 다른 알고리즘. 공개된 **수신자의 공개키로 암호화**하고 **수신자만 아는 개인키로 복호화**한다. (그림: A 송신자가 B의 공개키로 암호화 → B 수신자가 B의 개인키로 복호화) (p.50)
- **대칭키 암호화**: 통신하는 두 사람만 아는 같은 키를 사용해 암호화, 복호화를 한다. (p.50)

사례 1 — **패스워드 암호화** (p.50)
- 사용자 패스워드를 서버에 저장할 때 **해시 함수로 암호화된 패스워드(해시값)**를 저장한다.
- 해시 함수는 **암호화만 가능**하므로 암호화된 패스워드가 유출되어도 패스워드를 복원할 수 없다.
- **해시 함수**: 별도의 키 없이 입력할 때 일정 규칙을 적용해 **고정된 길이의 해시값**을 출력한다.
- 과정: 회원 가입 시 비밀번호(예: 1234) → 해시 함수 → 해시값(5d2cdaa……)을 데이터베이스에 저장 / 로그인 시 입력한 비밀번호의 해시값과 저장된 해시값을 비교. 적용된 규칙에 따라 **입력이 같으면 출력도 같다**.

사례 2 — **디지털 서명** (p.50)
- 네트워크에서 공개키 알고리즘을 활용하여 **송신자의 신원을 증명**하는 방법
- 송신자의 **개인키**로 원문의 해시값을 암호화하여 송신자 서명을 생성 → 수신자는 **송신자의 공개키**로 서명을 복원하여 검증
- 즉 공개키 알고리즘과 **키 사용이 반대**이다.
- 그림 흐름: A가 메시지에 해시 함수 적용 → 해시값을 A의 개인키로 암호화 → 디지털 서명 / B는 수신된 서명을 A의 공개키로 복호화한 해시값과, 수신된 메시지에 해시 함수를 적용한 해시값을 비교해 검증

사례 3 — **안전한 데이터 통신 HTTPS 암호화** (p.50)
- 웹 브라우저와 웹 사이트 간에 데이터를 주고받을 때 데이터를 암호화하여 안전하게 통신
- **공개키 암호화**로 외부 인증 기관이 인정한 안전한 웹 사이트인지 확인하고, 전송하는 데이터는 **대칭키 암호화**로 암호화하여 통신
- 안전한 웹 사용을 위해 사이트 주소가 'https'로 시작하는지 확인한다.

### 선택 활동 1 — 고대 암호를 이용해 암호화, 복호화하기 (p.51)
1. 카이사르 암호(암호화 키 = 3)
   - ⑴ 평문 `Manners Maketh Man`을 암호화 (p.51)
   - ⑵ 암호문 `Eh Fduhixo iru Dvvdvvlqdwru`를 복호화 (p.51)
2. 카이사르 암호의 한계와 비즈네르 암호 (p.51)
   - **카이사르 암호의 한계**: 암호문의 문자는 항상 같은 평문의 문자로 대응되기 때문에, **문자의 출현 빈도**를 이용해 쉽게 해독할 수 있다.
   - **비즈네르 암호 방식**: 암호화 키에 따라 A → 0, B → 1, C → 2, …… 으로 **이동하는 수를 바꾼다**. 키를 반복해서 평문 아래에 놓는다.
   - ⑵ 평문 `HELLOWORLD`, 암호화 키 'BAG'(B A G B A G B A G B) → 이동 수 및 교과서 표에 제시된 값 기반 암호화 (p.51)
- 스스로 평가하기: 데이터 암호화·복호화 과정을 이해하고 평문을 암호화·복호화할 수 있는가? (p.51)

## 비교·정리표

### 대칭키 암호화 vs 공개키 암호화
| 구분 | 대칭키 암호화 | 공개키 암호화 |
|---|---|---|
| 키 관계 | 암호화 키 = 복호화 키 | 암호화 키 ≠ 복호화 키 |
| 사용 키 | 통신하는 두 사람만 아는 같은 키 | 수신자의 공개키로 암호화, 수신자의 개인키로 복호화 |
| HTTPS에서 역할 | 전송하는 데이터를 암호화 | 외부 인증 기관이 인정한 안전한 사이트인지 확인 |

### 전치 암호 vs 치환 암호
| 구분 | 전치 암호 | 치환 암호 |
|---|---|---|
| 방법 | 평문 문자의 자리를 바꿈 | 평문 문자를 다른 문자로 대체 |
| 사례 | 스키테일 암호 | 카이사르 암호 |
| 근대 | 에니그마 등 기계 장치가 둘을 혼합 | (같음) |

### 현대 암호화 활용 사례
| 사례 | 쓰는 기술 | 핵심 |
|---|---|---|
| 패스워드 암호화 | 해시 함수 | 해시값 저장, 암호화만 가능 → 유출돼도 복원 불가 |
| 디지털 서명 | 공개키 알고리즘(키 사용 반대) + 해시 | 송신자 개인키로 서명, 송신자 공개키로 검증 → 신원 증명 |
| HTTPS | 공개키 + 대칭키 | 사이트 인증은 공개키, 데이터는 대칭키 |

### 공개키 암호화 vs 디지털 서명의 키 사용
| 구분 | 암호화에 쓰는 키 | 복호화(검증)에 쓰는 키 |
|---|---|---|
| 공개키 암호화 | 수신자의 공개키 | 수신자의 개인키 |
| 디지털 서명 | 송신자의 개인키 | 송신자의 공개키 |

### 고대·근대 암호 사례
| 사례 | 시대 | 방식 | 예 |
|---|---|---|---|
| 스키테일 | 고대 | 전치 | Secret Message → Stse acMgreees |
| 카이사르 | 고대 | 치환(키만큼 평행 이동) | SECRET → VHFUHW (key=3) |
| 에니그마 | 근대(제2차 세계 대전, 독일) | 배전반 1차 치환 + 회전자 2차 치환 | 회전자 1개당 676가지 |

## 시험 함정 포인트
- 암호화 키와 복호화 키가 **같으면 대칭키**, **다르면 공개키** 암호화다. 반대로 외우지 않는다. (p.48)
- 공개키 암호화는 송신자의 키가 아니라 **수신자의 공개키로 암호화**하고 **수신자의 개인키로 복호화**한다. (p.50)
- 디지털 서명은 공개키 암호화와 **키 사용이 반대**다: **송신자의 개인키**로 서명하고 **송신자의 공개키**로 검증한다. 목적은 비밀 유지가 아니라 **송신자의 신원 증명**이다. (p.50)
- HTTPS는 공개키만 쓰는 것이 아니다. 사이트 확인은 **공개키**, 전송 데이터 암호화는 **대칭키**다. (p.50)
- 해시 함수는 키가 **필요 없고**, 암호화만 가능하며(복원 불가) 출력은 **고정된 길이**다. 입력이 같으면 출력도 같다. (p.50)
- 서버는 패스워드를 그대로 저장하는 것이 아니라 **해시값**으로 저장한다. (p.50)
- 스키테일은 치환이 아니라 **전치 암호**, 카이사르는 전치가 아니라 **치환 암호**다. (p.49)
- 에니그마는 고대가 아니라 **근대** 암호(제2차 세계 대전, 독일의 기계식 암호기)이고, 1차 치환은 **배전반**, 2차 치환은 **회전자**다. (p.49)
- 회전자 1개의 경우의 수는 26이 아니라 **676(= 26 × 26)**이다. (p.49)
- 카이사르 복호화는 키만큼 **반대로** 이동한다. (p.48)
- 카이사르 암호의 한계는 키가 짧다는 것이 아니라 같은 평문 문자가 **항상 같은 암호 문자로 대응**되어 **출현 빈도**로 해독된다는 것이다. 비즈네르는 키에 따라 **이동 수를 바꾼다**. (p.51)
- 숫자판 암호에서 같은 평문도 **서로 다른 숫자 암호문**이 될 수 있다(같은 글자가 여러 칸에 있음). (p.52)

## 핵심 용어 사전
| 용어 | 뜻 |
|---|---|
| 디지털 데이터 암호화 | 권한이 없는 사람이 데이터를 알아볼 수 없게 변환하는 기술 |
| 암호화(encryption) | 평문을 암호문으로 바꾸는 과정 |
| 복호화(decryption) | 암호문을 평문으로 복원하는 과정 |
| 평문 | 누구나 읽을 수 있는 암호화되지 않은 데이터 |
| 암호문 | 평문을 암호화한 결과 |
| 키(key) | 암호 알고리즘에서 평문을 암호문으로 바꿀 때 쓰는 문자열(암호화 키) |
| 대칭키 암호화 | 암호화 키와 복호화 키가 같은 방식 |
| 공개키 암호화 | 암호화 키와 복호화 키가 다른 방식(수신자 공개키로 암호화, 개인키로 복호화) |
| 전치 암호 | 평문 문자의 자리를 바꿔 암호화 |
| 치환 암호 | 평문 문자를 다른 문자로 대체해 암호화 |
| 스키테일 암호 | 나무 막대기에 양피지 리본을 감아 쓰는 고대 전치 암호 |
| 카이사르 암호 | 키만큼 평행 이동한 문자로 바꾸는 고대 치환 암호 |
| 에니그마 | 제2차 세계 대전 독일의 기계식 암호기 |
| 회전자 | 입력 문자 26개와 출력 문자 26개를 연결하는 회전판 |
| 비즈네르 암호 | 암호화 키에 따라 이동 수를 바꾸는 암호 |
| 해시 함수 | 키 없이 일정 규칙으로 고정된 길이의 해시값을 출력하는 함수 |
| 해시값 | 해시 함수의 출력값 |
| 디지털 서명 | 송신자 개인키로 해시값을 암호화해 신원을 증명하는 방법 |
| HTTPS 암호화 | 웹 브라우저와 사이트 간 데이터를 암호화하는 안전한 통신 |

## 자기점검 질문
1. 암호화와 복호화를 구성하는 두 요소는? — 키와 암호 알고리즘
2. 키 관리가 중요한 이유는? — 올바른 복호화 키를 가진 사람만 암호문을 해독할 수 있으므로
3. 카이사르 암호 key = 3으로 LOVE를 암호화하면? — ORYH
4. 스키테일과 카이사르 암호는 각각 어떤 방식인가? — 전치 암호, 치환 암호
5. 해시 함수로 저장한 패스워드가 유출되어도 안전한 이유는? — 해시 함수는 암호화만 가능해 원래 패스워드를 복원할 수 없으므로
6. 디지털 서명에서 서명 생성과 검증에 쓰는 키는? — 송신자의 개인키로 생성, 송신자의 공개키로 검증
7. HTTPS에서 공개키와 대칭키는 각각 무엇에 쓰인가? — 공개키: 인증 기관이 인정한 안전한 사이트인지 확인 / 대칭키: 전송 데이터 암호화
8. 카이사르 암호의 한계는? — 같은 평문 문자가 항상 같은 암호 문자로 대응되어 출현 빈도로 쉽게 해독됨
9. 에니그마의 암호화 순서는? — 키보드 입력 → 배전반 1차 치환 → 회전자 2차 치환 → 발광판 출력
10. 숫자판 암호에서 숫자 두 자리는 각각 무엇을 뜻하나? — 가로줄(행) 숫자와 세로줄(열) 숫자
