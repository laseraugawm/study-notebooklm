## 핵심 개념

### 1. 딕셔너리(dictionary)
- **딕셔너리**: 파이썬에서 데이터를 저장하는 방식 중 하나로, **키(key)와 값(value)이 쌍**으로 이루어진 데이터 집합 (p.161)
- 만드는 규칙 (p.161)
  1. 중괄호 `{ }` 를 사용해 만든다.
  2. 키와 값은 콜론 `:` 으로 구분한다.
  3. 각 쌍은 쉼표 `,` 로 구분한다.
- 예시: 원자 기호를 키로, 원자량을 값으로 가지는 딕셔너리 (p.161)

```python
atom = {'H':1, 'C':12, 'O':16}        # H: 수소, C: 탄소, O: 산소
print(atom['H'])
```

- `atom['H']` 처럼 **키로 값을 찾는다** → 실행 결과 `1` (p.161)
- 딕셔너리를 사용하면 각 원자의 원자량을 빠르게 찾을 수 있다. (p.161)

| 키 | 'H' | 'C' | 'O' |
|---|---|---|---|
| 값 | 1 | 12 | 16 |

### 2. 실습 3 — 화학식 양 구하기 (융합: 통합 과학)
**단계 1 문제 정의하기** (p.161)
- 과제: 화학식 양을 출력하는 프로그램 작성(단, 화학식에는 괄호가 없고 수소·탄소·산소만 포함)
- **화학식 양**: 그 화학식에 포함된 모든 원자의 질량의 합 (p.161)
- 원자 하나의 질량: 수소(H) 1, 탄소(C) 12, 산소(O) 16 (p.161)
- 예: 물(H2O) = 수소 원자 2개(H2) + 산소 원자 1개(O) → 1×2 + 16 = **18** (p.161)

**단계 2 프로그래밍하기** (p.161)

```python
chemical = input()
stack = []
atom = {'H':1, 'C':12, 'O':16}
for c in chemical :
  if c == 'H' or c == 'C' or c == 'O' :
    stack.append(atom[c])
  else :
    stack.append(stack.pop()*int(c))
print(sum(stack))
```

줄별 동작
- 01 `chemical = input()`: 화학식(예: H2O)을 문자열로 입력받는다.
- 02 `stack = []`: 원자 질량을 쌓아 둘 빈 리스트(스택)를 만든다.
- 03 `atom = {...}`: 원자 기호(키)–원자량(값) 딕셔너리.
- 04 `for c in chemical :`: 화학식 문자열을 한 글자씩 꺼내 c 에 넣고 반복한다.
- 05~06: c 가 'H', 'C', 'O' 중 하나이면 `atom[c]`(그 원자의 질량)를 스택에 추가(append)한다.
- 07~08: 그 밖의 글자(숫자)이면 스택의 마지막 값을 꺼내(pop) `int(c)` 배 한 뒤 다시 스택에 넣는다. → 바로 앞 원자의 개수만큼 질량을 곱하는 과정
- 09 `print(sum(stack))`: 스택에 남은 값의 합 = 화학식 양을 출력한다.

H2O 입력 시 스택 변화(코드 추적)

| 읽은 글자 | 동작 | stack |
|---|---|---|
| H | atom['H']=1 추가 | [1] |
| 2 | pop → 1×2=2 추가 | [2] |
| O | atom['O']=16 추가 | [2, 16] |
| 끝 | sum → 18 출력 | — |

- 실행 결과: 입력 `H2O` → 출력 `18` (p.161)

### 6. 대단원 Ⅲ 마무리 — 개념 정리 (p.168)
- 01 문제 분해와 모델링: **문제 분해** = 복잡한 문제를 작은 문제로 분해하는 것 / **모델링** = 핵심 요소들 간의 관계를 단순하게 구조화하는 것
- 02 알고리즘: **정렬** = 수많은 데이터를 특정 기준에 따라 나열하는 과정 / **탐색** = 여러 개의 데이터 중에서 특정 데이터를 찾는 과정
- 03 프로그래밍의 이해: **변수** = 값을 저장하는 기억 공간 / **자료형** = 정수, 실수, 문자열 등 값의 형태 / **표준 입출력** = 키보드로 데이터를 입력받아 모니터로 출력하는 작업 / **파일 입출력** = 파일을 읽고 쓰는 작업 / **다차원 데이터 구조** = 데이터를 행과 열 또는 여러 개의 차원으로 구성하여 저장하는 구조

## 시험 함정 포인트
- 딕셔너리는 대괄호가 아니라 **중괄호 `{ }`** 로 만들고, 키와 값은 쉼표가 아니라 **콜론 `:`** 으로 구분한다. 쌍과 쌍 사이가 쉼표다. (p.161)
- `atom['H']` 는 'H' 를 출력하는 것이 아니라 키 'H' 의 **값 1** 을 출력한다. (p.161)
- 화학식 양 프로그램에서 숫자를 만나면 새 값을 추가하는 것이 아니라 **스택의 마지막 값을 pop 해 숫자만큼 곱한 뒤 다시 append** 한다. (p.161)
- 탐색적 데이터 분석 4단계 중 문제 정의·문제 해결은 **협력 활동**, 데이터 수집·데이터 분석은 **개별 활동**이다. (p.162)
- `ascending = False` 는 오름차순이 아니라 **내림차순**이다. (p.165)
- 1인당 전체 음식물 쓰레기양 1위는 대한민국이 아니라 **말레이시아**(다음 나이지리아, 르완다, 이스라엘, 그리스)다. (p.165)
- 우리나라 음식물 쓰레기 비중이 가장 높은 곳은 외식 산업이 아니라 **가정(HHS, 65%)** 이다. (p.166)
- 데이터프레임은 860개의 행·12개의 컬럼이며, 인덱스는 1~860이 아니라 **0~859** 다. (p.164)
- 조건 결과를 df1 에 저장하지 않으면 **재사용할 수 없어** 같은 조건을 매번 다시 써야 한다. (p.164)
- `isin()` 은 하나의 값이 아니라 **인자로 준 값들이 포함된 행**을 모두 선택한다. (p.165)
- `autopct="%.1f%%"` 는 비율을 **소수점 첫째 자리**까지 자동 계산해 표시한다. (p.166)
- 업로드한 파일은 내 컴퓨터가 아니라 **코랩 노트북이 실행되는 가상 환경 내부 폴더**에 저장된다. (p.163)
- 컬럼 '2019'는 연도가 아니라 **2019년 나라별 1인당 음식물 쓰레기양(kg)** 을 뜻한다. (p.164)
